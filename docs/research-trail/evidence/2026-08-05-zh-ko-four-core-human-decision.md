# 중→한 후속 코어 4건 블라인드 제시와 사용자 최종 판정

> 날짜: 2026-08-05
>
> 상태: **사용자 최종 판정 완료 · 개발·테스트 콘텐츠 · 미션/상태/DB 미변경**

## 1. 절차

2차 코어 저장분의 AI 보조 잠정 후보 4건에서 run ID·계획 번호·화행·모드·AI 판정을 숨기고,
`situation_ko`와 `source_text`만 A~D로 순서를 섞어 사용자에게 제시했다. 사용자는 블라인드
내용을 본 뒤 Fable의 교차 벤더 판정·사유를 확인하고 그 판정을 최종 확정했다.

따라서 이 결과는 **사용자의 사람 최종 결정**이지만, Fable 사유를 보기 전에 사용자가 독자적인
판정을 제출한 것은 아니므로 `independent_blind_human_review`로 표현하지 않는다.

## 2. 블라인드 키와 최종 판정

| 블라인드 | 계획 셀 | 실제 내용 | 사용자 최종 판정 | 핵심 근거 |
|---|---:|---|---|---|
| A | #29 | 불만·중급·번역 | 채택 | 상황의 세 문제와 원문이 대응하고 수신자가 조치 권한을 가진다. `场地安排`의 느슨한 요약과 `你/您` 화역은 차단하지 않는다. |
| B | #24 | 초대·중급·통역 | 기각 | 초대 화자와 통역 학습자가 같은 사람으로 서술된 역할 중첩. 원문에 없는 임상시험 일정 관리도 상황에 추가됐다. |
| C | #30 | 불만·중급·통역 | 기각 | 불만 화자와 통역 학습자가 같은 사람으로 서술됐다. 상황의 업무 전달 누락은 원문에 없다. |
| D | #23 | 초대·중급·번역 | 보류 | 상황·원문 대응은 양호하지만 `부담을 주지 않으면서도 정중하게`가 목표 화용 기준을 학습자 상황문에 노출한다. |

최종값은 **채택 1·보류 1·기각 2**다. A만 후속 탐색 조립 후보에 추가하고, B·C는 제외하며,
D는 원본 행을 직접 고치지 않고 별도 재생성·재판정 대상으로 남긴다.

## 3. 자동 게이트가 놓친 구조 결함

통역 B·C는 생성 프롬프트가 요구한 A(source 언어 화자) → 학습자 통역 → B(target 언어 화자)
구조를 만족하지 않는다. 그러나 현재 `coreBilingualSceneIssue()`는 상황문에 `중국어/한국어/통역`
문자열이 있는지만 확인하고, A와 학습자가 같은 사람으로 합쳐졌는지는 검사하지 않는다.

- 계약: `supabase/functions/generate-scenario/index.ts:1076-1078`
- 현재 검사: `supabase/functions/_shared/coreSourceRepair.ts:61-78`
- 결과: B·C 모두 C1 규칙과 C2를 통과했지만 사용자 최종 판정에서 기각

이는 화행별 target feature 실패가 아니라 **중→한 통역 장면의 참여자 역할 분리 검사 공백**이다.
검사·repair 보완은 이번 판정과 분리해 별도 코드 변경으로 다룬다.

## 4. 현행 생성 콘텐츠 전체의 수명 경계

사용자는 이 30셀 run만이 아니라 현재 DB에 존재하는 **모든 생성 코어와 학습 미션**을
프롬프트·문항·상황 시나리오·검수 체계를 개선하기 위한 개발·테스트 콘텐츠로 확정했다.

- 현재의 `reviewed`도 해당 시점의 개발·데모 사용 가능 판정이며 최종 정식 콘텐츠가 아니다.
- 후속 미션 조립은 M1·M3·C2와 E1의 탐색적 관찰을 위한 일회성 측정으로만 수행할 수 있다.
- 생성계약·target feature·PDR/역할·원문·문항·검수·프롬프트 등 콘텐츠 영향 조건을 LOCK한
  뒤 새 release와 run ID로 코어부터 미션까지 깨끗하게 전량 재생산한다.
- 현재 세대와 LOCK 뒤 정식 생산 세대를 섞지 않는다.
- 정리 전에 단계별 수치·호출 원장·실패 사례·관련 ID를 문서와 Git에 보존한다.
- 실제 DB 삭제·비활성화는 참조 관계와 정확한 범위를 읽기 전용으로 확인한 뒤 사용자의 별도
  파괴적 작업 승인으로 실행한다. 이 문서는 삭제 명령이 아니다.
- 사용자·인증 데이터, 원자료/source bank, 연구 기록, 호출 원장, 학습자 로그는 생성 콘텐츠
  정리 범위로 자동 확대하지 않는다.

세부 LOCK·refresh 절차는 `docs/operations/CONTENT_REFRESH_RUNBOOK.md`를 따른다.
