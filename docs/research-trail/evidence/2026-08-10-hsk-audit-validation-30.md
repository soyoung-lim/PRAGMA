# LOCK 전 HSK 어휘 감사 장치 30건 검증

## 목적과 해석 범위

- 목적은 HSK 어휘 감사 장치가 수준·언어 방향·모드가 달라져도 계약대로 계산·저장·표시되는지
  확인하는 것이다.
- 대상은 LOCK 전 테스트 콘텐츠이며, 최종 콘텐츠 품질·HSK 적합도·논문 성과를 추정하는 표본이 아니다.
- 이 30건과 감사 결과는 본생산 전 폐기 또는 연구 통계에서 제외한다.
- LLM을 다시 호출하지 않았다. 기존 중국어 텍스트의 토큰을 운영 HSK DB와 대조하고
  `hsk_lexical_audit` 필드만 기록했다.

## 표본 구성

- 계획: PRAGMA 수준 3 × 방향 2 × 모드 2의 12개 셀에서 각 2건(24건) + 경계 사례 6건.
- 실제: `중급 × 한→중 × 통역`의 조건에 맞는 미승인·미감사 행이 1건뿐이어서 기본 셀 23건 +
  경계 사례 7건으로 조정했다. 12개 셀은 모두 최소 1건을 포함한다.
- 수준: 입문 9, 중급 11, 고급 10.
- 방향: 한→중 13, 중→한 17.
- 모드: 번역 16, 통역 14. DB의 통역 정본 값은 `stt_interpreting`이다.
- 이미 승인·검토된 행과 기존 HSK 감사가 있는 행은 제외했다.

|---|---:|
| HSK 감사 계약 | 30/30 통과 |
| DB 저장 후 재조회 | 30/30 통과 |
| 외부 `content_hash`와 내부 콘텐츠 hash | 30/30 불변 |
| 고유 중국어 토큰 처리 | 1,345개 |
| 기준 범위 내 확인 | 1,053개 |
| 교수자 추가 확인 후보 | 292개 |

1,053/1,345 및 후보 292개는 장치가 텍스트를 분절하고 두 범주로 나누었다는 작동 증거일 뿐,
콘텐츠 품질이나 수준별 적합률을 뜻하지 않는다.

## 관리자 화면 연결과 발견한 결함

- 새 감사 결과는 한→중 13건이 mission 범위, 중→한 17건이 core 범위에 표시된다.
- `/admin/review?hsk=candidates`에서 mission 후보는 14건으로 보였다. 이 중 13건이 이번 표본이고
  1건은 앞선 E2E 기록이다. core 후보는 이번 표본 17건이다.
- 초기 화면은 Supabase 응답 상한 1,000행 때문에 오래된 검증 행 일부를 누락했다.
  `AdminReview` 조회를 1,000행 단위 전체 페이지 조회로 바꾸고 30건 모두 각 범위에서 보임을 확인했다.
