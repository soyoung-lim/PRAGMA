## 4. AI 초안 집계

| 유형 | 축 | 통과 | 보류 | 실패 |
|---|---:|---:|---:|---:|
| Type B | 5 | 5 | 0 | 0 |
| Type A | 5 | 2 | 2 | 1 |
| 합계 | 10 | 7 | 2 | 1 |

이 초안은 실행 전 예상 E1의 방향과 반대다. E1은 Type B의 과잉 실현·조립 성공이 Type A보다
높지 않을 것으로 예상했지만, AI 초안 정적 점검에서는 Type B 5/5, Type A 2/5만 통과했다.
그러나 예문 작성과 판정을 같은 AI가 수행했고 축마다 하나의 명제만 사용했으므로, 이를 E1의
반증이나 유형 차이로 보고하지 않는다. **Fable 교차검증 뒤에도 방향이 유지될 때만 소수 조립
대상 선정의 근거로 사용한다.**

## 6. Fable 교차검증 요청 지점

Fable은 보고서의 결론을 믿지 말고 카탈로그 정본과 각 3안을 직접 대조한다.

1. 10축 각각에서 세 안이 정말 동일 명제·동일 화행 의도를 유지하는가
2. 과소·과잉안이 문법·의미 오류나 우스운 극단이라 화용 지식 없이 소거되지는 않는가
3. 사과·칭찬 대응의 보류가 적절한가, 아니면 gate1 통과 가능한 대체 과잉안이 있는가
4. 불만 축의 실패가 구조적 충돌인가, 동일 명제를 보존하는 실사용 가능 3안이 있는가
5. 요청·거절·제안·초대·반대·칭찬하기의 통과가 과도하게 관대한가
6. Type B 5/5 대 Type A 2/5라는 방향 반전이 예문 선택 편향으로 생긴 것은 아닌가
7. 글자 수와 R5 해석이 코드 `checkMultiJudgeLength`와 맞는가

교차검증 결과는 `수용 / 보완 / 기각`과 축별 대체 문장으로 받아 합친다. 그 뒤에만 축 판정과
운영 후보 라우팅을 확정하고 소수 미션 조립 승인 여부를 다시 묻는다.
