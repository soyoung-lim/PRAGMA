## ITER-20260802-02 · 장면 진입에서 결과 소유·누적 보관까지 미션 경험 연결

- 날짜: 2026-08-02
- 시작 문제:
  - 1차 콜드 오픈은 장면과 차례를 한 화면에 함께 보여 줘 사용자가 장면 안으로 들어가는
    두 박자를 만들지 못했다.
  - `preceding_turn`이 비면 응답 화행도 개시형으로 표시해, 결측 legacy 자료에서 장면 의미가
    뒤집힐 수 있었다.
  - 완료 조언과 수정 지도가 분리됐고 누적 수정 노트로 돌아가는 동선이 없어, 수행→성취→
    소유→재방문의 제품 루프가 닫히지 않았다.
- 변경:
  - 선행 턴 실제 존재와 응답 화행을 함께 보는 3상태 순수 판정을 추가하고 nullable·공백·
    legacy를 회귀 테스트했다.
  - 콜드 오픈을 자동 진행 없는 `장면 열기`와 `당신 차례`로 분리하고 단계 전환 포커스를
    추가했다.
  - Take 1·2, 초점, 수정 전략, 개인화 조언을 하나의 완료 소유 카드로 통합했다.
  - exact 응답 비교를 표시·저장·기록의 공통 수정 판정으로 사용하고, 저장 성공+실제 수정일
    때만 기존 수정 노트 anchor를 연결했다.
- 실제 검증:
  - typecheck·변경 파일 ESLint·전체 **218 pass / 6 skip**·프롬프트 재생성 없는 production
    build(1898 modules) 통과.
  - localhost 데스크톱에서 수동 2단계 콜드 오픈, 자동 진행 없음, 번역 변경 있음/없음 완료
    카드와 데모 링크 비노출을 확인했다.
  - 통역 DEV 데모를 듣기·녹음/전사→피드백→수정 없음 완료 카드까지 완주했다.
  - 390×844 콜드 오픈과 변경 있음 소유 카드에서 수평 overflow가 없었다. 새 콘솔 오류는
    없고 기존 React Router future flag 경고만 있었다.
- 예상과 달랐던 점:
  - feasibility를 작은 화면 변경으로 해석한 1차 구현은 데이터 안전성은 지켰지만, 사용자에게
    필요한 제품화 목표를 과도하게 축소했다. 비용 통제는 목표를 낮추는 근거가 아니라 체감
    효과가 큰 연결부터 구현하는 순서 원칙이어야 했다.
  - 현재 localhost 세션은 인증 없는 데모라 실제 `saved` 링크 종단을 만들 수 없었다. DB 쓰기
    없이 확인 가능한 상태 정책은 순수 함수로 검증하고, 로그인 계정 smoke를 후속으로 남겼다.
- 다음 설계에 반영할 교훈:
  - 연구 불변조건과 제품 경험의 적극성은 별도 축으로 판단한다.
  - 사용자 피드백이 설계 목표선을 교정하면, 최초의 축소 범위를 고수하지 말고 연구 계약을
    해치지 않는 범위에서 전체 경험 루프를 다시 완결한다.
  - 실제 운영 검증 전에는 콘텐츠 재생성이나 `policy_ver` 인상을 하지 않는다.
- 관련 Decision / Evidence: `DEC-20260802-02`, `EVD-20260802-02`

  - 인앱 브라우저 564×731에서 수평 overflow 없음과 새 콘솔 오류 없음을 확인했다.

    `1504272b-af34-42e2-a0ce-7f6f75df7b1e`의 SUCCESS·RUNNING과 운영 미션 chunk의
    DM·번역 작성기·통역 수행 콘솔 문구를 확인했다.
- 예상과 달랐던 점:
  - 1차 구현은 channel을 연구 축으로 복원하지 않았지만, 통역 MPJ와 번역 DCT 표시 분기에는

    우선 설명하게 한다.
  - 통역은 번역과 시각 톤을 맞추되, 듣기·녹음이라는 수행 양식까지 문자 작성으로 바꾸지 않는다.

## ITER-20260802-04 · 콜드 오픈 정보 밀도·공간·단계 중복 시각 반복

- 날짜: 2026-08-02
- 시작 문제:
  - 운영 배포된 수동 2단계 콜드 오픈은 장면 진입 구조는 만들었지만, 메타 제목·안내문·상황·
    관계·노란 설명 카드가 중복돼 사건보다 설명서를 읽는 경험에 가까웠다.
  - 상대의 실제 `preceding_turn`이 화면의 주인공이 되지 못했고, 두 번 클릭해도 새로운 발견과

- 시도한 변경:
  - 장면과 상대 턴을 한 화면에 압축하고 진행 레일을 숨기는 실험.
  - 레일을 복구하고 `나—메시지—상대` 관계 도식으로 빈 공간을 채우는 실험.
  - 첫 화면을 큰 목표와 인물 사이드카드로 분할하고 두 번째 화면을 대형 대화 캔버스로 만드는
    실험.
  - 마지막으로 단일 세로 장면 카드와 MPJ와 다른 어두운 수신 사건 카드로 축소하는 실험.
- 실제 검증:
  - 각 반복을 전용 worktree의 localhost에서 응답형·개시형으로 확인했다.
  - 마지막 로컬 상태는 typecheck, 변경 파일 ESLint, 콜드 오픈 관련 11개 테스트를 통과했다.
  - 전체 218 pass/6 skip은 이 반복 중간 상태에서 통과했으나, 마지막 시각 조정 뒤 전체 suite와
    production build는 다시 실행하지 않았다.
  - DB·콘텐츠·스키마·프롬프트·`policy_ver`는 변경하지 않았다.
- 사용자 평가와 예상과 달랐던 점:
  - 정보 삭제만으로 임팩트가 생기지 않았고, 레일 삭제는 오히려 안정감을 낮췄다.
  - 화면이 비어 보인다는 문제를 카드 높이·폭 확대로 해결하려 하자 첫 화면은 발표 슬라이드처럼
    비례가 무너지고 두 번째 화면은 더 큰 빈 캔버스가 됐다.
  - 두 번째 콜드 오픈에 메신저 입력창·전송 버튼을 쓰면, 바로 다음 MPJ의 강한 DM 표면과
    시각적으로 같은 경험이 반복된다. 장면 몰입과 채널 모사는 같은 문제가 아니었다.
  - 마지막 compact 알림형 대안도 사용자 승인 전에 작업 종료가 결정돼 채택 근거가 없다.
- 다음 설계에 반영할 교훈:

- 관련 Decision / Evidence: `DEC-20260802-04`, `EVD-20260802-04`
