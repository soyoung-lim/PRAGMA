## ITER-20260729-01 · mission_v4 관계 맥락과 판단 피로 조정

- 날짜: 2026-07-29
- 시작 문제:
  - MPJ1 장면 정보가 좁은 공간에 촘촘하게 배치돼 장면의 중요성과 몰입감이 충분히 드러나지 않았다.
  - 모든 MPJ에서 상대의 선행 발화가 사라져 P·D·R의 관계 맥락과 대화감이 약해졌다.
  - MPJ3의 부적절 전제는 오류 신호가 약했다.
  - 최신 v4의 MPJ4에는 합의된 5후보 비교 방식이 반영되지 않았다.
- 변경:
  - 장면 카드의 높이·여백·문장 간격 확대
  - 네 MPJ의 target-language 선행 발화와 메신저 `오늘`
  - MPJ2 Judge 후 correction 순차 공개와 MPJ3 적색 오류 신호
  - 5후보 BEST 1·WORST 1, 전체 참고 대역 사후 공개
  - 번역 내용 어휘 힌트 2개·열람 trace와 통역 힌트 미제공
- 검증 결과:
  - typecheck 통과
  - 전체 141개 테스트 통과, 생성형 golden 3개 skip
  - 프롬프트 스냅샷 12종 재생성
  - production build 통과
  - localhost에서 MPJ1~4와 번역·통역 화면을 실제 클릭해 항목 수, 공개 순서와 계산 스타일을 확인
- 예상과 달랐던 점:
  - 앞선 수정은 최신 `mission_v4`가 아닌 구버전 worktree와 8093 서버에 들어가 실제 최신 화면에 나타나지 않았다. `1513155` 기준의 새 worktree에서 다시 구현했다.
  - BEST 2·WORST 1 보완안은 후속 사용자 결정으로 BEST 1·WORST 1로 바뀌었다.
  - 선행 발화를 복원하자 메신저가 이미 진행 중인 대화가 되어, 고정 인사말을 추가할 필요가 없어졌다.
- 다음 설계에 반영할 교훈:
  - localhost 링크를 안내하기 전에 서버 PID, worktree, branch, HEAD와 화면의 schema 배너를 함께 확인한다.
  - 후보 수, 학습자 응답 수와 사후 피드백 양을 각각 독립적으로 설계한다.
  - P·D·R은 설명문뿐 아니라 상대 발화와 대화 UI에도 일관되게 구현한다.
- 관련 Decision / Evidence: `DEC-20260729-02`~`DEC-20260729-05`, `EVD-20260729-01`, `EVD-20260729-02`

## ITER-20260729-02 · 화면 밀도·문항 변별력·단계명 2차 조정

- 날짜: 2026-07-29
- 시작 문제:
  - 장면 카드의 여유를 늘리는 과정에서 두 상황문 사이 간격이 과해졌다.
  - 메신저의 단독 `오늘` 표시는 실제 메신저를 닮기보다 장식처럼 보였다.
  - MPJ3 오답이 터무니없어 주원인 변별이 지나치게 쉬웠다.
  - MPJ4 BEST/WORST가 순차 단계로 나뉘고 선택 버튼이 후보 아래에 있어 비교 흐름과 화면 밀도가 좋지 않았다.
  - 번역 어휘 힌트 패널과 세 워크플로우 단계명이 실제 기능에 비해 불필요하게 넓거나 모호했다.
- 변경:
  - 장면 카드 높이는 유지하고 문장 사이 여백을 14px에서 8px로 조정
  - 메신저 날짜 구분 삭제
  - MPJ2 보조 문구를 `복수 선택 가능`으로 축약
  - MPJ3 오답을 호칭·기간 구체성에 관한 그럴듯한 인접 해석으로 교체하고 생성 규칙 강화
  - MPJ4를 한 화면의 5개 가로 행과 우측 BEST/WORST 태그로 재구성
  - 힌트 패널을 내용 폭에 맞춤
  - 단계명을 `표현 감각 익히기 → 직접 번역/통역하기 → 피드백 확인하기`로 변경
- 검증 결과:
  - typecheck 통과
  - 표적 23개 테스트와 전체 141개 테스트 통과, 생성형 golden 3개 skip
  - 프롬프트 스냅샷 12종 재생성
  - localhost에서 MPJ1 간격 8px·날짜 미노출, MPJ2 문구, MPJ3 선택지, MPJ4 5개 행의 동시 태그와 번역 힌트 폭을 확인
- 예상과 달랐던 점:
  - 장면 공간을 넓히는 것과 문장 자체를 멀리 떼는 것은 같은 조정이 아니었다. 컨테이너의 여유와 문장 리듬을 분리해 다뤄야 했다.
  - BEST/WORST 응답 수를 줄이는 것만으로는 충분하지 않았고, 다섯 후보를 동시에 볼 수 있는 비교 구조가 필요했다.
- 다음 설계에 반영할 교훈:
  - 인지부담 감소는 단계 수뿐 아니라 비교 대상의 동시 가시성과 선택 위치까지 함께 본다.
  - Reason 문항의 오답은 명백한 거짓이 아니라 인접 구인과 주원인을 구별하게 설계한다.
- 관련 Decision / Evidence: `DEC-20260729-06`, `DEC-20260729-07`, `EVD-20260729-03`

## ITER-20260729-03 · MPJ→DCT SUMMARY와 개인화 피드백 연결

- 날짜: 2026-07-29
- 시작 문제:
  - MPJ 네 문항을 모두 마쳐도 무엇을 구분해 판단했는지 정리하는 연결부가 없었다.
  - 다듬기의 `이번 수정 목표`와 완료 단계의 미션 요약이 일반 설명문처럼 보여 실제 응답과의 연결이 약했다.
  - 장면 카드에 공통 최소 높이를 주자 짧은 통역 장면에도 불필요한 빈 공간이 생겼다.
  - v4 미리보기에서 번역 뒤 통역으로 전환할 때 `preview=v4`가 사라져 구버전 샘플 또는 로그인 흐름으로 이탈했다.
- 변경:
  - 기존 handoff를 실제 MPJ 응답 네 개의 한 줄 개념 SUMMARY로 확장하고 중복되는 일반 판단 흐름은 삭제
  - 기존 피드백을 재사용해 다듬기 한 줄 수정 행동과 완료 단계 한 줄 조언을 구성
  - 장면 카드의 고정 최소 높이를 제거하고 공통 패딩·행간·문장 간격만 유지
  - 번역·통역 전환 시 v4 preview와 part 쿼리를 보존
- 검증 결과:
  - typecheck 통과
  - 전체 141개 테스트 통과, 생성형 golden 3개 skip
  - localhost 전체 클릭 흐름에서 SUMMARY 4개 행, 한 줄 수정 행동, 개인화 완료 조언과 v4 통역 전환 확인
  - SUMMARY 행 45px, 데스크톱 코멘트 17.1875px 한 줄, 수정 행동 24.375px 한 줄, 피드백 판정 카드 88px로 확인
- 예상과 달랐던 점:
  - 모든 장면 카드에 같은 고정 높이를 주는 것은 밀도 통일이 아니었다. 내용이 짧은 통역 장면에서는 같은 패딩과 행간만 공유하는 편이 시각적으로 더 일관됐다.
  - 번역에서 통역으로 넘어갈 때의 구버전 노출은 콘텐츠 문제가 아니라 미리보기 쿼리 유실 때문이었다.
  - SUMMARY와 완료 조언은 새 생성 호출 없이 이미 수집한 MPJ 응답과 피드백 결과로 구성할 수 있었다.
- 다음 설계에 반영할 교훈:
  - 단계 사이 handoff는 일반 원칙을 반복하기보다 직전 수행을 다음 과업의 인지 흐름으로 조직해야 한다.
  - 개인화 피드백은 문장 길이보다 `현재 답안 → 다음 행동` 연결을 우선하고, 기존 판정 데이터로 충분한지 먼저 확인한다.
  - 공통 컴포넌트의 시각 통일은 고정 크기가 아니라 패딩·행간·정보 위계 같은 밀도 규칙으로 관리한다.
- 관련 Decision / Evidence: `DEC-20260729-08`, `EVD-20260729-04`
