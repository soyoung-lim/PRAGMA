## DEC-20260815-03 · 최종 9화행 기준답안은 Gold45로 고정한다

- 날짜: 2026-08-15
- 상태: main·운영 DB·Edge·웹 적용 완료, 실제 Gold45 구축 전
- 문제: 30건을 9화행으로 나누고 화행당 2건을 최초 외부 표본으로 뽑으면 표본이 모집단의 60%이고 화행별 예비가 1~2건뿐이라, 문제 지적 시 확전 규칙이 실질적으로 작동하기 어렵다. 기존 30건은 요청·거절·감사 3화행 각 10건이라 최종 9화행 모집단도 아니다.
- 검토한 대안:
  1. 9화행×4=36: 최초 2건 뒤 예비가 화행당 2건이라 확전은 가능하지만, 최종 불합의나 추가 결함 뒤 재확인 여유가 작다.
  2. 30건을 유지하고 화행당 최초 표본을 1건으로 축소: 표본 부담은 줄지만 전문가 간 독립 판정의 화행별 초기 범위가 너무 얇다.
  3. 9화행×5=45: 최초 2건을 유지하면서 화행당 예비 3건을 고정할 수 있다.

## DEC-20260823-01 · A4 이유를 판정 잠금 뒤 3지선다로 고정한다

- 날짜: 2026-08-23
- 상태: Mission V4 미리보기와 운영 Mission V1 reason 흐름·수행 로그 반영 완료, V4/mission_v5 단계 구성 조정 전
- 문제:

  - 매주 두 미션에서 자유서술을 반복하면 화용 판단보다 쓰기 부담이 커지고 응답 범주를 비교·집계하기 어렵다.
  - 확신도는 현재 연구 질문과 직접 연결되지 않으면서 단계와 반복만 늘릴 가능성이 컸다.
- 검토한 대안:
  1. 자유서술 유지: 학습자의 언어를 보존하지만 짧고 불균질한 응답이 많아질 수 있고 화용적 이유 구별에 불필요한 쓰기 변인을 더한다.
  2. 판정 뒤 확신도 추가: 메타인지 자료는 얻을 수 있으나 현재 분석 계획과 직접 연결되지 않아 범위 확장으로 판단했다.
  3. 판정 잠금 뒤 이유 3개 중 하나 선택: 판단과 근거를 분리하면서 짧은 시간 안에 구조화된 오개념 자료를 남길 수 있어 채택했다.
- 결정:
  - A4 코어 순서를 `판정 선택 → 판정 잠금 → 이유 3개 중 1개 선택 → 이유 확인 → 짧은 피드백`으로 고정한다.
  - 세 이유는 `primary`, `pragmatic_misconception`, `meaning_grammar_context`를 하나씩 포함하고, 정답은 배열 위치가 아닌 `acceptedReasonId`로 지정한다.
  - 이유 문구는 P·D·R 기호를 직접 시험하지 않고 학습자가 표현과 상황에서 관찰할 수 있는 언어로 쓴다.
  - 코어 응답에는 `judgment`와 `reasonId`만 남긴다. 자유서술과 confidence는 넣지 않으며 이견 제기는 후속 선택 경로로 분리한다.
  - 이유 확인 전에는 참고 판정·권장 이유·피드백을 공개하지 않는다.
  - 운영 runner는 같은 결정을 `band_code`, `reason_id`, `reason_kind`의 비채점 trace로 보존하고, 최초·수정 산출·피드백·이견과 같은 수행 로그 행 안에서 서로 덮어쓰지 않게 한다.
- 근거: 정본 `PRAGMA_생성계약_정본.md`와 `PRAGMA_학습자구조_정본.md`가 이미 3개 이유·정답 1개·confidence 제외를 규정한다. 이번 결정은 새 미션 버전을 선언하는 것이 아니라 V4 표시층을 정본에 맞추는 조정이다.
- 주장 경계: DB 기반 Mission V1의 기존 `learner_mission_logs` 저장 봉투까지 연결했지만 실제 원격 DB insert와 학습효과는 검증하지 않았다. V4 로컬 이견은 여전히 저장되지 않으며, MPJ5 화면인 V4와 MPJ4 정본 `mission_v5`의 구성이 조정되기 전에는 UUID 라우트를 V4로 교체하지 않는다. append-only `learner_mission_events` 연결도 이번 범위가 아니다.
