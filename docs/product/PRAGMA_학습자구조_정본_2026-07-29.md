# PRAGMA 학습자 구조 정본

> 상태: 2026-07-29 한국시간 기준 현재 정본
> 적용 범위: 학습자 정보구조, 수업·주차 흐름, 미션 수행, 학습 노트, 기록, 라운지, 연구윤리 경계
> 이전 문서: 2026-07-21 학습구조 문서는 결정 이력 보존용이며, 현재 동작과 충돌하면 이 문서가 우선한다.

## 1. 학습자 경험의 목적

PRAGMA의 학습자 화면은 검사 응시 화면이 아니라 수업과 연결된 학습 환경이다.

> 실제 상황에서 적절한 한·중 통번역 수행을 연습하고, 그 원리를 화용론적으로 이해하도록 돕는다.

학습자에게는 상황과 Can-do 수행 목표를 먼저 보여준다. 화행, P·D·R, `target_feature`, 모드와 방향은 교수설계·생성·연구 층에서 구조화해 유지한다.

## 2. 최상위 정보구조

하단 메뉴는 4개다.

```text
홈 | 수업 | 라운지 | 기록
```

| 메뉴 | 경로 | 역할 |
|---|---|---|
| 홈 | `/learner/home` | 현재 수업 상태와 다음 행동 |
| 수업 | `/learner/course` | 강좌·주차·배정 학습 진입 |
| 라운지 | `/learner/lounge` | 미션과 분리된 저부담 쉬어가기 |
| 기록 | `/learner/records` | 학습자가 확인할 수 있는 수행 기록 |

현재 원칙:

- 구 메뉴명 `과정`은 학습자 화면에서 `수업`으로 표시한다.
- 홈에 라운지 진입 카드를 중복 배치하지 않는다.
- `자유 연습` 준비중 타일을 표시하지 않는다.
- 학생이 500개 코어를 검색·추천받아 자율 선택하는 경로는 현재 논문·프로토타입 범위 밖이다.
- 셀프 학습 기능이 실제로 생기기 전에는 최상위 탭이나 자리표시자를 만들지 않는다.

## 3. 학습자 진입과 연구동의

### 3.1 학습 이용

- 승인된 학습자는 프로필 설정 후 수업 화면에 진입한다.
- 학습 이용과 연구 참여는 별개다.
- 연구 미동의 상태라도 동일한 학습 기회를 가져야 한다.

### 3.2 연구동의

- 프로필 온보딩에서 간단한 필수 연구동의 팝업을 받지 않는다.
- 기관 승인 설명문, 자료 범위, 보관·철회 절차가 준비된 별도 동의 흐름을 사용한다.
- 기존 동의 컬럼과 관리자 조회는 호환을 위해 남아 있을 수 있으나, 신규 온보딩은 동의 값을 학습 접근 게이트로 쓰지 않는다.
- 운영 로그가 있다는 사실만으로 연구 분석에 사용할 수 없다.

## 4. 수업·주차 구조

### 4.1 수업연계형 단일 경로

PRAGMA의 공식 학습 경로는 교강사가 편성·게시한 15주 수업이다.

```text
수업
→ 주차
→ Can-do와 예습 자료
→ 배정 미션
→ 복습 자료
→ 기록
```

- 공통 필수 미션은 주차의 핵심 수행이다.
- 선택 복습 미션이 있다면 교강사가 배정한 범위 안에서 제공한다.
- 학습자가 미검수 코어나 `generated` 미션을 직접 고르지 않는다.
- 학습자 실행 최소 조건은 `mission_status='reviewed'`다.

### 4.2 Can-do

Can-do는 상황·참여자·목적·수행·모드·상황 적절성 기준을 학습자 언어로 설명한다.

- 화행을 대체하지 않는다.
- 특정 완화 표현의 사용 자체를 성공 기준으로 고정하지 않는다.
- 입문·중급·고급을 CEFR·ACTFL 등급과 대응시키지 않는다.
- 교수자가 저장한 주차 Can-do를 우선 사용한다.
- 저장 Can-do가 없을 때만 결정론적 보조 가이드를 사용한다.

관련 원칙은 `docs/research/PRAGMA_CAN_DO_ALIGNMENT_PRINCIPLES_2026-07-28.md`를 따른다.

## 5. 주차 학습 노트

경로:

```text
/learner/course/week/:weekNo/note
```

학습 노트는 웹에서 읽고 브라우저 인쇄로 PDF 저장할 수 있다.

### 5.1 예습면

- 주차 Can-do
- 상황과 관계를 읽는 기준
- 일반적 화용 원리
- 미리 생각할 질문

### 5.2 복습면

- 활용 가능한 표현 자원
- 표현별 인상 비교
- 혼동하기 쉬운 판단 기준
- 예외·반례
- 자신의 표현에 대한 성찰

### 5.3 공개 규칙

```text
교수자 공개
OR
해당 주차 필수 미션 전체 완료
→ 복습면 공개
```

- 첫 제출이나 일부 미션 완료만으로 열지 않는다.
- 필수 미션이 없는 주차를 자동 완료로 간주하지 않는다.
- 해금 전 인쇄본에는 예습면만 포함한다.
- 해금 후 예습면과 복습면을 함께 포함한다.
- 노트 열람 자체를 학습 효과나 성취의 증거로 해석하지 않는다.

구현 메모:

- 학습 노트와 공개 제어 코드는 구현돼 있다.
- `curriculum_weeks.review_released` migration 파일이 존재한다.
- 2026-07-28 작업 로그 기준 원격 적용은 별도 확인 대상이며, 확인 없이 프로덕션 적용 완료라고 쓰지 않는다.

## 6. Full Mission 학습 흐름

학습자 정본 경로:

```text
/learner/practice
```

### 6.1 신규 Full Mission

신규 `mission_v4`의 학습 흐름:

```text
표현 감각 익히기
  첫인상 판단
    Scale4 원응답 → 적절/부적절 방향 피드백
  → 판단하고 고쳐보기
    Judge3 1회 → 수정안 4개 중 적절한 2개 선택
  → 왜 문제일까
    부적절함을 전제 → 가장 큰 이유 1개/3개 선택
  → 여러 초안 비교
    후보 5개를 한 화면에서 비교
    → 각 행의 태그로 BEST 1 + WORST 1 선택
    → 제출 뒤 과소 2 + 적정 2 + 과잉 1 참고 판정 공개
  → 네 판단 정리
    실제 응답 4개를 문항별 판단 기능과 이번 장면의 판단 기준을 연결한 한 줄 SUMMARY로 제시

직접 번역하기 또는 직접 통역하기
  번역 또는 통역 산출

피드백 확인하기
  → 피드백
  → 세 층 모두 통과: 현재 표현으로 완료 / 다른 표현 선택 시도
  → 조절 필요: 다듬기 → 완료
```

- MPJ 4개와 DCT 1회가 하나의 미션이다.
- 1부 완료는 미션 완료가 아니다.
- 2단계에서는 판단을 반복하지 않고 곧바로 독립 산출한 뒤 피드백을 본다.
- 세 피드백 층을 모두 통과한 답안에는 수정을 강제하지 않는다. 그대로 완료하면 최초 산출을 최종 산출로 함께 보존한다.
- 다른 표현을 선택적으로 시도하거나 조절이 필요한 경우에는 최초 산출과 수정 산출을 구분해 보존한다.
- 첫 문항은 독립 Scale4다. 4점 원응답은 보존하되 적절/부적절 방향만 맞으면 인정하고, 매우/다소 차이는 참고 판정과 수업 토론에 사용한다.
- Judge3는 FixChoice에서만 묻는다. 판단을 제출한 뒤 교정안을 공개해 `판단 → 교정` 순서를 보존한다.
- Reason은 Judge3를 반복하지 않고 확신도를 묻지 않는다.
- MultiJudge는 후보마다 Judge3를 반복하지 않는다. 다섯 후보를 한 화면에서 비교하면서 각 행 오른쪽의 BEST/WORST 태그로 하나씩 고르고, 참고 대역은 제출 뒤 공개한다.
- 선택지·후보 수는 수준별로 바꾸지 않는다.
- 완료 시 MPJ에서 실제로 고른 선택은 `mpj_response_v1` 비채점 trace로 수행 로그에 함께 보존한다.
- FixChoice의 Judge3와 교정 선택은 같은 문항 응답으로 묶는다. Reason에는 존재하지 않는 확신도 값을 만들거나 저장하지 않는다.
- 참고 판정과 일치하지 않았다는 사실만으로 오답 점수나 능력 점수를 만들지 않는다.
- 번역+통역 연계 방향은 `번역`, `통역`, `번역 우선 paired`, `통역 우선 paired`의 과목 설정형이다. 다만 저장 계약이 필요한 2차 범위이므로 현행 v4에는 한 가지 주 수행만 존재하며, 데모의 수행 방식 전환은 companion 학습 구현으로 간주하지 않는다.

### 6.2 legacy 호환

- 기존 `mission_v1/v2` MPJ5와 `mission_v3` MPJ4는 계속 열 수 있다.
- `/learner/practice`의 샘플 데이터는 legacy `SAMPLE_MISSION_V1`일 수 있어 신규 v4와 다르게 보일 수 있다.
- 샘플·데모의 수행 방식 전환 단축은 실제 학습자의 완료 계약으로 일반화하지 않는다.

### 6.3 맥락과 전이

- P·D·R 코드는 학습자에게 그대로 노출하지 않는다.
- `역할/관계/부담` 같은 기계적 메타데이터 제목도 학습자에게 나열하지 않는다.
- 상황문은 `나는 지금 누구에게 무엇을 하려 한다`는 1인칭 현재 장면으로 시작한다. 이어지는 문장에서 위계·권한, 접촉 이력·친밀도, 부탁이나 행위의 실제 부담이 자연스럽게 보여야 하며 문장마다 줄을 나눠 읽기 쉽게 표시한다.
- `상대`에는 학습자가 마주한 상대의 역할·관계만 표시한다. 학습자 자신의 역할이나 `화자 → 상대` 도식은 함께 넣지 않는다.
- `첫인상 판단`은 소박한 규칙이 깨지는 적절한 대비 상황이다.
- `판단하고 고쳐보기`와 `왜 문제일까`는 DCT와 같은 PDR의 서로 다른 사건이다.
- `여러 초안 비교`는 P·D·R 중 한 축만 바꾼 대비 사건이다.
- DCT는 같은 PDR의 새 사건으로 근접 전이를 연습한다.

주간 한 미션만으로 넓은 상황 전이를 달성했다고 표시하지 않는다. 학기 전체에서 PDR 조건을 순환하고 통합 과제 수행을 통해 별도로 확인한다.

## 7. 미션 화면과 스캐폴딩

### 7.1 상황 제시

- 관계와 장면은 자연어로 제시한다.
- P·D·R 원시 코드를 학습자 화면에 그대로 노출하지 않는다.
- 상황 카드에는 `지금, 이 장면`이라는 진입 신호와 문장 위계를 두되, 별도의 역할·관계·부담 표를 만들지 않는다.
- 메신저 장면은 대화형, 이메일은 문서 초안형, 대면·전화는 발화형 시각 문법을 사용한다.
- mission_v4의 모든 MPJ에는 상대의 target-language 선행 발화를 표시해 P·D·R의 상대와 관계를 실제 대화 맥락으로 드러낸다. 별도의 날짜 구분은 표시하지 않는다.
- UI용 `channel`은 연구·난이도 축이 아니라 장면을 정확히 표현하기 위한 메타다.
- 통역은 듣기·녹음·전사 확인의 오디오 프레임을 사용한다.
- 미션 상단은 target feature 정본명을 그대로 노출하지 않고 `화행 + 학습자가 수행할 행동 문장`으로 풀어 쓴다. 이 초점과 3단계 워크플로우는 사이트 헤더 아래에 고정해 긴 화면에서도 현재 위치를 유지한다.
- MPJ 4개 뒤에는 새 학습 단계를 추가하지 않고 기존 handoff를 개인화 SUMMARY로 사용한다. 각 문항은 `첫인상 판단 / 판단하고 고쳐보기 / 이유 찾기 / 여러 초안 비교`의 기능과 실제 응답에서 확인한 판단 기준을 한 줄로 연결한다. 성공 문구는 화행 공통 문구가 아니라 target feature 카탈로그의 기능별 SUMMARY를 사용한다. 참고 판정과 다른 행만 수업 비교를 안내하며, 별도의 일반 흐름 문장은 반복하지 않는다.
- 직접 번역·통역 단계는 SUMMARY 뒤에 상황과 산출 도구로 곧바로 진입하며, MPJ 내용을 일반 설명문으로 다시 반복하지 않는다.
- MPJ와 직접 표현 단계 모두 장면 카드와 실제 대화·산출 도구를 별도 패널로 분리한다. 번역 화면의 단계명은 `번역하기`, 장면 신호는 `지금, 직접 번역할 장면`, 메신저 상태는 `메시지 작성 중`으로 표시한다. 장면 카드는 고정 최소 높이를 두지 않고 공통 패딩·행간·문장 간격을 사용해 내용에 맞는 높이로 표시한다.
- 한→중 번역에서 막힐 때 여는 힌트는 입력 말풍선 바로 위 우측의 작은 보조 행동으로 둔다. 기본은 접힘 상태이며, 펼칠 때는 산출을 막는 비화용적 내용 어휘·고유명사·전문용어 두 개만 한 줄로 보여 준다. MPJ에서 학습한 완화 표지나 정답 문장 구조는 제공하지 않고, 열람 여부와 최초 시각을 비채점 trace로 남긴다. 통역에는 힌트를 제공하지 않으며, 완성 답안은 제출 뒤에 공개한다.
- MPJ의 장면·메신저는 판단 대상인 문제 영역으로 가볍게 유지하고, 선지 카드는 네이비 상단선으로 `여기서부터 응답`임을 구분한다.

### 7.2 판단과 피드백

- AI 판정은 현재 수업 기준의 참고 판정이며 절대적 판결로 표시하지 않는다.
- 의미, 명백한 문법 문제, 화용 초점을 분리한다.
- 의미층은 사실·조건·핵심 화행 내용의 보존을 확인하고, 강도·완화·선택권·명료성·범위 같은 목표 화용 자원의 변화는 상황 적절성 층에서만 다룬다. 이 경계는 요청·거절·감사·사과 등 화행에 관계없이 동일하다.
- “더 길게”, “더 완곡하게”를 일반 정답 규칙으로 가르치지 않는다.
- Reason은 `가장 큰 이유는 무엇인가요?`로 단일 주원인만 묻는다.
- Reason의 오답도 실제 표현이나 인접한 화용 쟁점을 근거로 한 그럴듯한 설명으로 만들되, 주원인과 동등하게 방어 가능해서는 안 된다.
- 피드백 화면은 내 답을 가장 선명하게 보여 준 뒤 `의미 전달 / 문법 정확성 / 상황 적절성`을 동등한 세 기준으로 제시한다. 번호는 쓰지 않으며, 각 카드는 상단의 기준·상태와 하단의 구체적 피드백을 안정된 2단 위계로 보여 준다.
- `AI`는 피드백 주 제목에서 반복 강조하지 않고 하단 참고 고지에만 남겨, 학습 흐름과 생성 주체 투명성을 함께 지킨다.
- 세 층 모두 통과하면 `이 표현으로 완료`를 주 행동으로, `다른 표현도 시도해보기`를 보조 행동으로 제공한다. 하나라도 조절이 필요하면 `한 번 다듬어보기`로 연결한다.
- 참고 표현과 의견 남기기는 유지하되, 상세 판정 근거는 학습자 주 흐름에 노출하지 않는다.
- 수정 화면은 `이번 수정 목표 → 수정 전 → 수정 후 입력` 순서다. 수정 목표는 AI 피드백 문단을 반복하지 않고 판정 결과에서 도출한 한 줄 행동으로 제시한다.
- 완료 화면은 수정 전후와 바뀐 부분, 해당 답안에 맞춘 한 줄 조언, 저장 상태와 다음 행동만 남긴다. 판정 결과가 없을 때만 일반 원칙 한 줄을 대체 문구로 사용하고, 예외 규칙·표현 목록·라운지 진입을 완료 단계에서 반복하지 않는다.

### 7.3 주장 경계

- 미션 점수 하나로 화용 능력 전체를 나타내지 않는다.
- 시도 횟수·힌트 감소를 성장 지표로 표시하지 않는다.
- 발음, 유창성, 성조 정확성을 채점하지 않는다.
- 실제 상호작용 능력이나 교육 효과를 자동으로 입증한다고 주장하지 않는다.

## 8. 라운지

### 8.1 역할

라운지는 핵심 미션의 높은 인지부하를 완충하는 저부담 참여 지원 공간이다.

- 미션과 무관
- 점수·감점 없음
- 연구·학습 수행 기록에 미반영
- 별도 탭과 별도 시각 언어
- 미션 완료를 입장 조건으로 사용하지 않음

### 8.2 경로와 코너

```text
/learner/lounge
/learner/lounge/theater
/learner/lounge/meme
/learner/lounge/decoder
```

| 코너 | 현재 목업 |
|---|---|
| 생생극장 | 짧은 장면의 표현 뉘앙스 + 선택형 통역 도전 |
| 밈 배틀 | `脆皮打工人` 번역 캡션 3개 중 목업 투표 |
| 해독실 | 관계·채널이 있는 디지털 담화를 한국어 선택으로 해독 |

### 8.3 수준 정책

- 화면에서 입문·중급·고급 선택을 제공하지 않는다.
- 라운지는 하나로 열고 콘텐츠 안에서 표현 난도를 자연스럽게 변주한다.
- 내부 데이터에는 `difficulty` 메타만 남긴다.
- `difficulty`는 향후 순서·추천·교수자 배정에 활용할 수 있으나 현재 개인화 기능은 아니다.
- 프로필의 중국어 수준과 라운지를 자동 매핑하지 않는다.

### 8.4 현재 구현 범위

- 로컬 목업 콘텐츠
- 라운지 전용 DB·Edge·관리자 입력 화면 없음
- 밈 투표 저장 없음
- 생생극장 실제 영상 embed 없음
- 해독실 완료 표시는 기기 localStorage에만 저장
- XP, 배지 경제, streak, 리더보드, 개인화 추천 없음

해독실은 단순 숫자 뜻 퀴즈가 아니라 다음을 한 문항 안에서 연결한다.

```text
발신자·수신자·채널
→ 표현의 뜻과 태도
→ 관계에 맞는 한국어 번역 선택
→ 번역 이유
```

별도 `눈치 체크` 단계는 두지 않는다.

## 9. 기록

기록 화면은 학습자가 실제로 수행한 미션과 수정 이력을 확인하는 곳이다.

- 코어 수나 생성 성공 수를 학습 성취처럼 표시하지 않는다.
- 라운지 활동을 합산하지 않는다.
- 연구동의 상태를 학습 진행률로 표시하지 않는다.
- 기술적·탐색적 과정 자료와 학습자용 진행 표시를 구분한다.
