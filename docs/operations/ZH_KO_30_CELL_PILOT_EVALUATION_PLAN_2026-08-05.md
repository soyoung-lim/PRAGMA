# 중→한 30셀 혼합 파일럿 실행 전 판정 계획

- 확정일: 2026-08-05
- 상태: **첫 원격 생성 호출 전 고정**
- 관련 결정: `DEC-20260805-01`, `DEC-20260805-02`
- 성격: 내부 버전 기록이 있는 **실행 전 판정 계획**. 외부 등록소에 맡긴 정식 사전등록으로 부르지 않는다.

## 1. 목적과 범위

이 파일럿은 중→한 콘텐츠를 곧바로 54셀 본배치로 확대하지 않고, 현재 생성·검수
워크플로우가 9화행에서 작동하는지 탐색적으로 점검한다. 학습 효과나 방향 간 우열을
검증하는 실험이 아니다.

고정 범위는 다음 30셀이다.

- 핵심 3화행(요청·거절·감사): 3수준 × 번역/통역 = 18셀
- 확장 6화행(사과·제안·초대·반대·칭찬·불만): 중급 × 번역/통역 = 12셀
- 방향: `zh_ko`만
- 셀당 계획 코어: 1건

이번 실행에서 하지 않는 것:

- 54셀 확대, ko_zh와 통과율 합산·우열 비교
- 프롬프트·모델·R규칙·오류 패턴 변경
- 생성물을 자동으로 `reviewed`로 승격
- 기존 콘텐츠 삭제·소급 수정, 학습자 배정, Railway 배포

## 3. 분석 단위와 분모

한 개의 통합 ‘성공률’을 만들지 않는다. 아래 단계를 각각 독립적으로 보고한다.

| 단계 | 분석 단위와 분모 | 기록값 |
|---|---|---|
| P0 계획 | 고정 계획 30셀 | 화행·수준·모드·plan index |
| C1 코어 생성 | 30셀 | 저장 성공/실패, R결과, repair, 오류 코드 |
| C2 코어 AI 점검 | 코어가 생성되어 점검 가능한 셀 | pass/warning/fail/호출 실패 |
| H0 코어 사람 선별 | 사람이 실제로 연 셀 | 적격/보류/기각 + 사유 |
| M1 미션 최초 성공 | H0 적격 코어 중 미션 조립 대상 | 1회차 규칙 non-fail 여부 |
| M3 미션 최종 성공 | 같은 대상, 최대 3회 | 3회 안 규칙 non-fail·저장 여부, 실제 시도 수 |
| Q 미션 AI 점검 | 규칙 non-fail 뒤 점검 응답이 있는 미션 | pass/warning/fail/호출 실패 |
| H 미션 사람 판정 | 사람이 실제로 검토한 generated 미션 | 사용 가능/보류/기각 + H1~H4 |
| R 상태 승격 | 사용자에게 별도로 승격 승인을 받은 미션 | reviewed 여부·검토자·시각 |

- 전송 오류에 대한 같은 요청의 backoff는 콘텐츠 생성 시도 수와 구분한다.
- M1과 M3을 함께 보고해 재시도로 가려진 최초 실패를 보존한다.
- 코어 실패로 미션을 조립하지 못한 셀은 미션 실패 분모에 억지로 넣지 않고 단계 이탈로 기록한다.
- 계획 수, 코어 생성 수, generated 수, 인간 사용 가능 수, reviewed 수를 서로 바꿔 쓰지 않는다.

## 4. 사람 판정 기준

### H0. 코어 적격

다음을 모두 만족하면 미션 조립 대상으로 삼는다.

1. 중국어 원문과 한국어 목표 방향이 맞고 언어 혼입이 없다.
2. 상황·역할·선행 발화·화행·P·D·R이 서로 모순되지 않는다.
3. 번역/통역 모드에 맞는 서면·구두 장면이며 원문이 해당 수준에서 수행 가능하다.
4. 중국어 원문이 자연스럽고 중심 명제·화행 의도가 식별된다.
5. 학습자 상황문이 평가 기준을 미리 답처럼 노출하지 않는다.

### H1~H4. 미션 사용 가능성

- **H1 불변항:** target·교정안·후보·추천안·참고안이 원문의 명제·의도·화행을 보존한다.
- **H2 대역 타당성:** 부적절성은 의미 손실이 아니라 해당 화용 초점의 과소·적정·과잉 차이다.
- **H3 한국어 화역:** 한국어 후보가 번역투·기계투가 아니며 상황에 맞는 자연스러운 화역이다.
- **H4 경계 사례:** 화용 지식 없이 제거할 수 있는 극단 후보가 판정 후보의 절반을 넘지 않는다.

최종 사람 판정:

- `사용 가능`: H1~H4 통과, 차단할 내용 결함 없음
- `보류`: 판단에 원어민·지도교수 확인이 필요하거나 경계가 확정되지 않음
- `기각`: H1/H2 위반, 화행·대역 오분류, 심각한 부자연성, 과업 불성립

`사용 가능` 판정도 자동 `reviewed` 승격 명령이 아니다. 상태 승격은 사용자가 별도로 결정한다.

## 5. 실행 전 탐색적 예상

정본에 근거가 없는 `Type A/Type B`를 새 화행 유형이나 새 구인으로 만들지 않는다. 다만
대역의 약한 쪽을 실현할 때 명제·화행 의도 소실과 가까워질 수 있는 다음 세 화행을
**경계 취약군**으로 묶어 기술적으로 확인한다.

- 제안(`proposal`): 지나친 유보로 제안 내용이 흐려질 위험
- 초대(내부 키 `agreement`): 응답 기대를 흐리는 것과 초대 의도 소실의 경계
- 반대(`opposition`): 지나친 완화로 실제 이견이 가려질 위험

실행 전에 고정하는 예상은 다음과 같다.

- E1. 경계 취약군의 인간 사용 가능 비율은 나머지 화행보다 높지 않을 것으로 예상한다.
- E2. 자동 규칙·AI 점검의 non-fail 비율은 인간 사용 가능 비율보다 높거나 같을 것으로 예상한다.
- E3. zh_ko 오류 힌트 수가 화행·방향별로 다르므로 ko_zh와의 통과율 차이를 방향 효과로 해석하지 않는다.

경계 취약군은 6셀, 나머지는 24셀이고 수준 구성도 다르다. 따라서 원자료 `n/N`과 사례를
기술할 뿐 유의성 검정, 인과 주장, ‘유형 검증’ 표현을 사용하지 않는다. E1이 관찰되지 않아도
사후에 화행을 다른 집단으로 옮기거나 분모를 바꾸지 않는다.

## 6. 중지·진행 기준

다음 중 하나면 남은 원격 호출을 중지하고 보고한다.

- 코드·Edge·content release·prompt hash가 실행 계획과 불일치
- 요청 모델과 반환 모델 불일치 또는 fallback 발생
- 같은 스키마·언어 방향·화행 오류가 연속 2셀에서 반복
- 호출 원장 적재 실패, run/item 식별자 충돌, 저장 계보 불명
- 기존 `reviewed`·실험 잠금·학습 로그 참조 행에 영향을 줄 가능성 발견

30셀 코어 생성 완료가 미션 조립 자동 승인을 뜻하지 않는다. C1·C2·H0 결과를 먼저 보고한 뒤
미션 조립으로 넘어간다. 미션 조립 완료도 54셀 확대나 본배치 자동 승인을 뜻하지 않는다.
