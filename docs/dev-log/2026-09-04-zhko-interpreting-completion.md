# 중→한 통역 정식 학습 경로 연결

## 시작 문제

- 중→한 번역을 정식화하면서 중→한 통역을 논문 버전 범위 밖으로 잘못 제한했다.
- 기존 생성 계약, TTS·STT Edge 함수와 legacy 음성 수행 프레임은 양방향을 지원했지만 정본
  런타임이 통역 미션을 거부해 실제 배정 경로에서 같은 기능을 사용할 수 없었다.
- 한국어 통역 전사가 후속 피드백 단계에서 중국어 답안 검증을 받아 탈락할 수 있었다.

## 변경

- 정본 미션 런타임을 `ko_zh`·`zh_ko`의 source/target 언어와 `translation`·`interpreting`
  모드로 일반화했다.
- 중→한 통역 DCT에 다음 흐름을 연결했다.
  - 중국어 원발화 TTS 재생(미션 재생 제한, 기본 2회)
  - 브라우저 마이크 한국어 통역 녹음
  - 기존 STT Edge 함수의 한국어 전사
  - 학습자 전사 확인·수정 뒤 확정 전사 제출
- 원발화 텍스트는 통역 화면에 노출하지 않는다. 녹음은 로컬 재생과 STT 요청에만 사용하고 DB에
  저장하지 않으며, 확정한 전사만 피드백·완료 기록으로 넘긴다. 통역에는 어휘 힌트를 표시하지 않는다.
- 한국어/중국어 목표어별 답안 검증과 통역·번역별 피드백·완료 문구를 분리했다.
- 중→한 통역의 A/B/C 역할과 기능적 등가를 legacy·core·mission·quality·feedback 프롬프트
  스냅샷에 고정하고 릴리스 후보 버전을 양방향 계약으로 올렸다.
- 생성 계약·학습자 구조 정본에서 중→한 통역 제외 문구를 대체하고 결정·반복 기록을 남겼다.

  중국어 TTS 요청 → 녹음 → 한국어 STT → 전사 확인 → 확정 전사 제출까지 모의 상호작용으로 검증했다.
- `npm.cmd run typecheck`: 통과.
- 최신 main 통합 뒤 전체 회귀검사: **119 files 통과, 3 files 스킵 / 706 tests 통과,
  9 tests 스킵**.
- `npm.cmd run prompts:verify`: 결정성 스냅샷 2종 통과. 프롬프트 스냅샷은 34종이며
  core surface hash `a73b79367c7f…`를 확인했다.
- 변경 파일 ESLint: 오류 0, 기존 `CanonicalMissionRun.tsx`의 fast-refresh·hook 경고 4건.
- Edge 검수 번들을 재생성한 뒤 `npm.cmd run build`: 통과. production source·프롬프트·검수 번들
  사전 검증과 Vite **1,968 modules** 변환을 완료했다. 기존 CSS 구문·500 kB 청크 경고는 남아 있다.

- 최신 main `859f8a7`을 병합하고 대시보드 기록 `-01`, 중→한 번역 `-02`, 중→한 통역
  `-03`으로 연구 기록 ID를 충돌 없이 정렬했다. 기능 코드 충돌은 없었고 신형 대시보드도
  전체 회귀에 포함됐다.
