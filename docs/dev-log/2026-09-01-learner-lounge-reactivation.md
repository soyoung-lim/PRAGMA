# 학습자 독립형 정적 라운지 재활성화

## 시작 문제

- 학습자 하단 메뉴가 `수업 | 기록` 두 칸뿐이라 화면과 탐색 구조가 과도하게 비어 보였다.
- 구 라운지 소스는 남아 있었지만 생생극장·밈 배틀·해독실 구조와 localStorage 완료 표시는
  현행의 가벼운 독립 학습 공간 및 연구 비기록 경계와 맞지 않았다.
- 관리자 자산의 자동 공개나 AI 웹 발굴 파이프라인을 만들면 핵심 미션 답 유출, 검수 부담,
  별도 CMS 개발로 범위가 커질 수 있었다.

## 결정

- 하단 정보구조를 `수업 | 기록 | 라운지` 3탭으로 바꿨다. 라운지는 필수 학습과 수행 회고보다
  부차적인 선택 활동이므로 마지막에 둔다.
- 라운지는 강좌·주차·미션·수행 기록과 독립된 정적 선택 활동으로 한정했다.
- 해독실·문화코드·직역 함정에 각 10개, 총 30개의 사례를 TypeScript 카탈로그로 구현했다.
- 기존 오류 유형·표현 후보·원자료 분석은 지식 공급원으로만 일방향 재사용하고, 실제 핵심 미션의
  문장·후보·해설은 복사하지 않는다.
- 앱 안의 AI 발굴, 웹 수집, 자동 게시, 관리자 CMS, DB·Edge·진행 저장은 만들지 않았다.

## 구현

- `src/lib/lounge/loungeTypes.ts`에 공통 메타와 모듈별 판별 타입을 정의했다.
- `decodeItems.ts`, `cultureItems.ts`, `literalItems.ts`에 모듈별 10개 정적 사례를 분리했다.
- 문화코드는 확인된 사실·문화 맥락·번역 해석, 출처 URL·확인일을 별도 필드로 보존한다.
- 모든 사례는 `source_checked`로 두었다. 연구자 최종 판정을 AI가 대신해
  `researcher_approved`로 올리지 않았다.
- `LoungeHub.tsx`와 `LoungeModulePage.tsx`에서 모듈 선택, 사례별 선택, 기준 확인, 이전·다음을
  제공한다. 정답 점수·완료율·성취 표시는 없다.
- `/learner/lounge/{decode,culture,literal}`를 추가했다. 구 `decoder`는 `decode`로,
  `theater`·`meme`는 라운지 허브로 돌리고 구 소스는 삭제하지 않았다.

## 스크린샷 피드백 반영

- 허브를 viewport 가운데로 정렬하고 `10개 사례 보기`를 삭제했다.
- 최상단은 기존 PRAGMA 남색·노랑 브랜드로 복구하고, 라운지 본문과 하단 탭에만 별도 색 체계를
  적용했다. 세 모듈의 장면 카드는 각각 청록·보라·코럴 계열로 구분했다.
- 모듈 소개 카드와 반복 설명을 없애고, 데스크톱에서 상황과 선택·해설을 나란히 보는 2열 구조로
  압축했다.
- 문화코드는 숫자·인터넷 표현을 제외하고 `春运`을 첫 사례로 둔 관습·제도·사회 현상 10개로
  재구성했다.
- 직역 함정은 화용 판단을 제외하고 `발표→发表`를 첫 사례로 둔 단어·한자어·결합 관계 10개로
  재구성했다.
- `발표` 첫 사례의 질문을 자연스러운 한국어로 고치고 선택 후 기준·설명 본문을 14~16px로 키웠다.
- 후속 피드백에서 모듈 캔버스를 `max-w-4xl`·330px로 줄이고 중앙 정렬했다. 세 장면 색은
  청록·인디고·코럴 솔리드로 조정해 글자 대비와 모듈 구분을 함께 높였다.
- 30개 제목을 짧은 질문형으로 정리하고 공통 질문을 모듈별 한 문장으로 통일했다. 선택 후에는
  정답 선택지에 `✓`, 선택한 오답에 `×`를 표시하고 아래에는 사례별 `quick_point` 한 줄만
  보여 준다. 기존 상세 해설과 출처는 데이터에 보존했다.
- 직역 함정 10개는 오류 표현 찾기에서 **가장 자연스러운 번역 고르기**로 전환했다. 기준 답을
  자연스러운 조정안으로 바꾸고, 복수 정답처럼 보이던 보기는 하나의 최선안이 드러나도록 정리했다.
- 문화코드 원문이 긴 사례는 시나리오 열을 넓히고 13~15px로 조절해 데스크톱에서 한 줄로 표시한다.
- 중국어 원문과 중국어 선택지에는 프로젝트 표준 `Noto Serif SC` 클래스(`font-zh`)를 명시적으로 적용했다.

- 라운지·하단 내비게이션 표적 4파일: **14 tests 통과**.
- 전체 회귀: **116 files 통과·3 skipped, 692 tests 통과·9 skipped**.
- `npm.cmd run typecheck`: 통과.
- 변경 파일 ESLint: 통과.
- 최종 `npm.cmd run build`: 통과, Vite **1,962 modules** 변환. 기존 전역 CSS 구문 경고와 500 kB
  청크 경고는 남았으나 라운지 허브·모듈·카탈로그는 별도 지연 로드 청크로 생성됐다.
- 로컬 브라우저 1280×720에서 허브의 중앙 정렬·수량 문구 제거, 세 모듈의 선택 전후 단일 화면,
  `春运`·`发表` 첫 사례와 하단 `수업 | 기록 | 라운지` 순서를 확인했다.
- 같은 viewport에서 330px 축소 캔버스, `✓/×`와 한 줄 포인트, 세 모듈 솔리드 색, 문화코드
  긴 `老字号` 원문의 한 줄 표시와 하단 이동 영역 비침범을 확인했다.
- 카탈로그 테스트로 새 라운지 30개 원문이 비라운지 production 소스에 그대로 존재하지 않는지,
  새 라운지 runtime이 Supabase·Query·local/session storage를 참조하지 않는지 검사했다.

## 범위와 남은 판정

- 생성 프롬프트·생성 계약·DB schema·연구 로그는 변경하지 않았다.
- 기능 커밋 `07f7a9d`를 `codex/learner-lounge-30-2026-09-01`에 푸시했다. 같은 커밋의 추적
  파일 764개만 분리해 Railway production에 직접 배포했고 deployment
  `9bed411c-5508-4a09-8426-d16403a5efc2`의 `SUCCESS`·instance `RUNNING`을 확인했다.
  공개 URL은 `https://pragma.up.railway.app`이며 비로그인 라운지 직접 접근은 기존 정책대로
  `/student-login?next=%2Flearner%2Flounge`로 이동했다.
- 첫 worktree 전체 업로드 시도는 로컬 `node_modules` 탐색으로 지연되어 중단했고, 그 잔여 시도
  `ad863e05-d1dc-486e-953c-a0b68961c25a`는 `FAILED`로 끝났다. 정리된 소스 배포가 이를 대체하며
  운영 active deployment는 성공 상태다.
- **확인 필요:** 30개 사례는 운영에 반영됐지만 상태는 계속 `source_checked`다. 배포 승인을
  사례별 `researcher_approved` 판정으로 소급하지 않는다. 이번 구현은 라운지의 학습효과나 문화
  해석의 보편성을 입증하지 않는다.
