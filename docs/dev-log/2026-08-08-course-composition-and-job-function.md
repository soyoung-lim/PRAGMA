# 교수자 교과목 편성 네 축 통합과 직무 기능 축

- 날짜: 2026-08-08
- 범위: 관리자 강좌 구조·편성, 단일 생성기의 직장 맥락, 생성계약·연구 기록

## 변경

- `/admin/composer`를 단일 `15주 강좌 편성` 작업대로 삼고, 별도 메뉴였던 `/admin/curriculum`은
  이 화면으로 리다이렉트한다. 빠른 `새 강좌`와 `주차 계획 수정`은 같은 경로의 전환 모드로 연다.
- 기존 편성기의 프리셋, 수준·주제·통역 비율·언어방향 네 축, 자동 채우기,
  주차별 교체와 저장 기능은 그대로 유지했다.
- 주차 기본 편집은 유형·제목·수업 초점 화행·미션 수·선택 Can-do·복습 공개로 줄였다.
  P·D·R·채널·도메인·산업·부하 밴드·역량 초점은 매주 수동 선택하는 기본 UI에서 제거했다.
- 네 축 중 수준·방향뿐 아니라 선택 주제·목표 통역 비율도 강좌의 자동 편성 정책으로 저장하는
  migration을 작성했다. 적용 전 legacy 행은 실제 배정에서 한 번 복원해 이전 동작을 보존한다.
- 자동 채우기는 선택 주제를 자동 완화하지 않는다. 부족 주차·슬롯을 표시하고 교강사가
  `다른 주제까지 확대해 다시 채우기`를 눌렀을 때만 범위를 넓힌다.
- 구조 저장은 주차 delete/reinsert를 없애고 주차 번호별 upsert를 사용한다. 구조 편집과 편성 저장은
  reviewed·수준·방향·주차 유형·화행·미션 수를 확인하는 공통 호환성 검사를 사용한다.
- 미션 편성 저장도 기존 전체 삭제를 먼저 하지 않고 새 편성을 upsert한 뒤 빠진 기존 행만 정리한다.
- 실화면 재검토 뒤 사이드바의 단독 `커리큘럼·수업 준비` 그룹을 없애고, 강좌 편성·학습자 관리·
  수행 기록을 `3 · 수업·학습 운영` 한 묶음으로 재구성했다.
- `새 강좌`는 기존 15주 편집기 전체를 중첩하지 않고 제목·수준·언어방향만 받는 빠른 생성
  모드로 바꿨다. 표준 15주안은 자동 생성하고 예외는 별도 `주차 계획 수정` 모드에서 바꾼다.
- 신규 강좌 INSERT에서 아직 운영 DB에 없는 편성 정책 열을 제외했다. migration 적용 뒤에는
  DB 기본값(전체 주제·통역 30%)이 같은 초기 정책을 채우므로 전후 동작이 일치한다.
- 편성 저장도 schema-cache의 정책 열 미존재 오류를 감지하면 수준·방향과 실제 미션을 저장하는
  호환 모드로 재시도하고, 주제·통역 목표가 실제 배정에서 복원된다는 경고를 표시한다.
- 기능 통합 뒤 AI 역량이 조용해 보인다는 후속 검토를 반영해 화면명과 사이드바를
  `AI 15주 교과목 설계`로 바꾸고, `교과목 설정 → AI 자동 편성 → 주차별 조정` 3단계 흐름을
  화면 상단에 추가했다. 프리셋과 `AI 자동 채우기`는 네 축 조건과 함께 배치했다.
- 첫 시각안의 서로 다른 세 색 카드와 행 우선 2열 주차 카드는 사용자가 정보 경쟁·지그재그
  읽기로 판정해 폐기했다. 세 단계는 전체 네이비 상단선을 공유하는 하나의 흰색 단계 바로
  통합하고 제목을 키운 명사형 문구로 줄였다. 네 편성축은 고정 폭의 개별 제어 블록으로 구분하고
  주제는 복수 선택 수와 다양성 안내를 함께 보인다. 주차는 왼쪽 1~8주·오른쪽 9~15주처럼 각 열
  안에서 아래로 읽는 열 우선 2단 목록으로 바꾸고, 반복 화행 라벨·`배정 0`·강한 주차 배지는 제거했다.
- 후속 비교 화면에서 필드 폭만 줄이고 페이지 작업면은 넓게 유지한 문제가 확인됐다. Composer 본문
  전체를 최대 960px의 왼쪽 정렬 작업 캔버스로 제한하고, 교과목 선택은 얇은 스트립, AI 편성은
  네이비 헤더·옐로우 실행 버튼·4축 블록을 가진 독립 핵심 패널, 주차 목록은 결과 영역으로 분리했다.
- 교과목 미선택 상태에서도 핵심 자동화 패널과 프리셋·네 축을 항상 노출한다. 이 상태의
  `AI 편성 시작`은 빠른 교과목 생성으로 연결하고, 먼저 정한 네 축을 새 교과목의 초깃값으로 넘긴다.
- 1080px 화면의 첫 시야에 핵심 패널 전체가 들어오도록 Composer 전용 상하 여백, 단계 바,
  교과목 스트립, 네 축 카드와 상태 행의 높이를 압축했다. 글로벌 헤더와 같은 진한 네이비였던
  핵심 패널 헤더는 글로벌 헤더와 구분되는 잉크 네이비(`#1E2F3A`)로 조정해 PRAGMA의
  색상 일관성을 유지했다.
- 운영 화면 후속 점검에서 내부 헤더 제목·프리셋·실행 버튼의 타이포를 한 단계 낮췄다. 수준·언어방향·
  모드 카드의 반복 노란 상단선은 중립 테두리로 바꾸고, 강의 맥락을 결정하는 주제 블록에만 노란
  포인트를 남겼다. 패널의 세로 여백과 기능 배치는 유지했다.
- 미션 재료 라이브러리의 작업 캔버스를 최대 1080px로 제한하고, 소개 문구와 코어 수·필터를 한 줄
  중심의 밀도 높은 도구막대로 재구성했다. `화행 × 수준별 코어 분포`는 수량에 따른 옅은 농도 차와
  잉크 네이비 선택 상태로 탐색성을 높였고, 결과 목록은 같은 폭·읽기 폭 78자로 정렬했다. 생성 출처는
  `생성 정보` 안에 접어 시나리오와 직접 발화가 먼저 읽히도록 했다. 조회 조건과 데이터 의미는 유지했다.
- 수준별 제작 상태 3장, 코어·DB 재조회 상시 문구, RQ2 단계 설명과 반복 평가 안내를 제거했다.
  대신 현재 선택 조건에서 자동 편성 가능한 reviewed 미션 수만 한 줄로 표시한다.
- 주차별 표는 긴 상황을 두 줄로 접고 미션·모드·화용 초점만 남겼다. 모든 후보와 저장이
  reviewed-only이므로 반복 검토상태 열은 제거했고, 평가 주차는 한 줄 잠금 표시로 축약했다.
- Can-do와 복습 공개는 학습자 화면에서 실제 소비되는 것을 확인해 삭제하지 않고
  `학습자 화면 세부 설정` 안에 접었다. downstream 사용이 없는 주차 수 표시·학기 목표 입력은
  기본 주차 계획 UI에서 제거했다.
- 단일 생성기의 직장 도메인에 기존 산업 7종과 별도로 직무 기능 7종을 추가했다.
- `business_function`을 개요·코어 생성 프롬프트, 저장 payload와 snapshot에 결속했다.
- 495 대량 계획에서도 work 셀에 직무 기능 7종을 순환 배정하고, 각 수준의 일상·학업·직장
  비율이 정확히 1:1:1인지 회귀검사로 고정했다.
- 도메인은 일상·학업·직장 3종, 수준별 주변분포는 1:1:1, 전문성은 수준·산업·직무·주제로
  표현하는 결정을 정본에 반영했다.
- 기존 RPC가 `business_function`을 저장하도록 교체 migration을 작성했다. 원격에는 적용하지 않았다.
- 통합 검수·승인 화면은 작업 캔버스를 최대 900px로 제한하고 `생성 묶음 선택 → 미션 직접 검수 →
  교수자 승인`의 세 단계로 재구성했다. run은 아래 방향으로 열리는 검색형 생성 묶음 선택기로 승격하고,
  상태·검색을 기본 검수 조건으로 묶었다. AI 검사·후보 이력·prompt 지문은 `세부 필터`에 접었다.
  큐에서는 상황·원문·AI 점검을 먼저 읽게 하고 run·item·release 등 추적 정보는 미리보기 안에 배치했다.
  승인 판정과 일괄 검수 후보 안전조건은 변경하지 않았다.

## 검증

- 통합 편성 표적 회귀: mapper 2 + 편성 계획 11 = 13/13 통과.
- 앞선 직무 기능 표적 회귀: 편성 9 + 배치 계획 14 + 배치 재개 3 + 프롬프트 snapshot 9 = 35/35 통과.
- 전체 Vitest: 302 pass, 8 skip.
- `npm.cmd run typecheck` 통과.
- 변경 TS 파일 ESLint 통과. 함께 손댄 생성기의 기존 `any` RPC cast 2건도 생성 타입 기반 호출로 제거했다.
- production build 통과(1,906 modules, prompt snapshot 18종, core hash `4eb32e4fffae…`).
- `git diff --check` 통과.
- localhost 실화면:
  - 생성기: 직장 전용 산업·직무 배치와 직무 7종, 비직장 선택 시 두 필드 숨김.
  - 단일 편성기: 메뉴 1개, 저장 편성 16개 복원, 프리셋·네 축·자동 채우기·주차별 미션 유지 확인.
  - 주차 계획 수정: 같은 경로에서 열리고, 기존 강좌의 중복 수준·방향과 과도한 주차 입력이
    보이지 않는 것을 확인했다.
  - 선택 주제만으로 부족한 경우 6개 주차의 부족 슬롯을 표시하고, 명시적 주제 확대 버튼을
    제공하는 것을 확인했다. 저장하지 않고 reload하여 DB 편성 16개를 원상 복원했다.
  - `/admin/curriculum`이 `/admin/composer`로 리다이렉트되고 사이드바에 편성 메뉴가 1개임을 확인했다.
  - 사이드바의 `3 · 수업·학습 운영` 아래 편성·학습자 관리·수행 기록 3개가 함께 표시됨을 확인했다.
  - `새 강좌`에서 세 필드와 `강좌 만들고 편성 시작`만 표시되고, 프리셋·주차 카드·P·D·R이
    뒤에 중첩되지 않음을 확인했다. `주차 계획 수정`도 편성기를 숨긴 독립 편집 모드로 확인했다.
  - 실제 신규 저장은 운영 DB 변경을 피하려고 재실행하지 않았고, INSERT payload에 오류를 낸
    두 정책 열이 없음을 mapper 회귀검사로 고정했다.
  - 후속 정보 감량 화면에서 단일 PRAGMA 단계 바, 고정 폭 네 축과 프리셋·AI 자동 채우기, 현재 조건
    미션 16개, 열 우선 2단 주차 목록과 구분선형 미션 요약을 확인했다. 새 교과목은 세 필드와 자동 생성 결과
    3개만, 주차 수정은 주차 핵심 입력과 접힌 학습자 세부 설정만 노출되는 것을 확인했다.
  - 최대 960px 작업 캔버스와 독립된 네이비 AI 핵심 패널이 좁은 자동 브라우저에서도 깨지지 않고
    렌더되는 것을 확인했다. 넓은 사용자 화면의 최종 비율은 localhost 캡처로 재확인한다.
  - 교과목 미선택 기본 화면에서도 핵심 자동화·프리셋·네 축·`AI 편성 시작`이 보이고, 실행하면
    빠른 교과목 생성으로 이동하며 중급·한→중 초깃값이 전달되는 것을 확인했다.
  - 1,265×712 자동 브라우저에서 제목부터 미선택 핵심 자동화 패널 전체와 다음 결과 영역의 시작점까지
    스크롤 없이 표시되고, 밝아진 내부 헤더가 글로벌 네이비와 구분되는 것을 확인했다.
  - 후속 미세 조정 뒤 localhost에서 내부 헤더의 타이포 위계, 주제 단일 포인트, 기존 패널 높이 유지와
    콘솔 오류 0건을 확인했다. typecheck와 수정 파일 ESLint가 통과했다.
  - 미션 재료 라이브러리에서 1080px 캔버스, 압축된 코어·필터 도구막대, 화행×수준 분포의 수량 농도와
    선택 상태, 동일 폭 결과 목록·접힌 생성 정보를 확인했다. `거절 · 중급` 선택 결과 40개가 정상 갱신됐고
    콘솔 오류는 0건이었다. typecheck, `AdminBrowser.tsx` ESLint와 production build(1,903 modules)가 통과했다.
  - 통합 검수·승인 화면에서 검색형 생성 묶음 목록이 항상 아래로 열리고 선택 즉시 단일 run 범위가 적용되는
    것을 localhost에서 확인했다. 900px 작업면 안에 검수 절차·현황·검수 대상·선택 미션 검수를 하나의 작업 패널로
    통합했고, 선택 영역은 잘린 구분선이 아니라 사방 테두리가 있는 내부 액션 바로 렌더된다. 결과 카드 간격과 본문도
    함께 압축했다. typecheck와 `AdminReview.tsx` ESLint, 검수 안전조건 회귀 9건이 통과했다.
