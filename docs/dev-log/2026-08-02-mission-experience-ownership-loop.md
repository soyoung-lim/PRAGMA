branch `codex/mission-experience-2026-08-02` · 선행 구현 `66ec631` · 구현 `20f1894`

## 배경

1차 패치는 연구 계약을 보존하면서 번역 MPJ·DCT의 장면 표면을 바꿨지만, 콜드 오픈을
한 화면에 합치고 `preceding_turn` 결측을 모두 개시형으로 처리했다. 완료 화면도 기존
조언 카드와 수정 지도가 분리돼 있어, 사용자가 확인한 제품 목표인
`장면 진입 → 실제 수행 → Take 1·2 변화 확인 → 결과 소유 → 수정 노트에서 재발견`을
아직 완결하지 못했다.

이번 반복은 최초·수정 산출과 저장 계약을 그대로 둔 채 이 경험 연결을 완성했다.
콘텐츠·DB·스키마·프롬프트·평가·`policy_ver`는 변경하지 않았다.

## 변경

### 1. 콜드 오픈을 안전한 순수 판정과 수동 2단계 장면으로 전환

- `classifyColdOpen`은 실제 `preceding_turn`이 있으면 화행 메타데이터와 무관하게 응답
  장면으로 사용한다.
- 선행 발화가 없고 현재 생성·검사 규칙의 응답 화행(`refusal`, `opposition`)이면 화면에
  없는 발화를 만들지 않고 `response-fallback`으로 분기한다. 개발 환경에서만 경고한다.
- 나머지 nullable·공백·legacy 입력은 개시형으로 처리한다.
- 인트로는 자동 타이머 없이 `장면 열기`와 `당신 차례`를 학습자가 직접 넘긴다. 마지막
  CTA `표현 비교 시작하기`는 기존 MPJ로 진입한다.
- 단계 전환 뒤 새 제목에 포커스를 옮기며, 장면/CTA는 네이티브 버튼으로 유지했다.

### 2. 완료 화면을 방금 만든 레퍼토리 소유 카드로 통합

- 기존 조언 카드와 `RevisionMap`을 한 카드로 합쳤다.
- `Take 1 · 최초 작성`은 피드백 전 산출, `Take 2 · 피드백 후 수정`은 최종 산출로
  표시한다.
- 수정하지 않았으면 `Take 2 · 최종 확정 — 변경 없음`으로 표시해 두 번째 응답을
  만들어내지 않는다.
- 이번 초점, 수정 전략, 다음에도 기억할 조언을 같은 카드 안에 배치했다.
- 수정 여부는 저장·기록과 동일하게 정확히 `first_response !== revised_response`로
  판정한다. 공백 정규화나 의미 추정은 하지 않는다.

### 3. 실제 저장된 수정만 누적 보관소로 연결

- `saveState === "saved"`이고 최초·최종 산출이 실제로 다를 때만
  `나의 수정 노트에 저장됨 · 모아보기 →`를 표시한다.
- 링크는 `/learner/records#correction-notes`를 사용한다.
- 기록 화면은 재설계하지 않고, 비동기 조회 뒤 해시 대상이 생겨도 해당 섹션으로
  이동하도록 기존 섹션에 안정적인 anchor를 부여했다.
- 미수정·저장 중·저장 실패·데모 상태에는 수정 노트 저장 문구를 표시하지 않는다.
