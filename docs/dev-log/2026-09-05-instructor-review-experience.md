# 교수자 체험 감수와 AI 검토 연속 실행 · 2026-09-05

## 문제와 범위

사용자가 원자료 전문 읽기와 단계별 AI 호출 대기로 인한 감수 부담을 보고했다. 학생 화면을
직접 체험하며 판단하는 방식과 반복 클릭 제거를 먼저 구현했다. 보고된 29건은 사용자 경험의
맥락이며 시간 측정이나 부담 감소 효과의 실측 자료로 취급하지 않는다.

이번 단계는 개별 미션의 교수자 최종 승인을 유지한다. 층화 표본·lot 승인·미열람 콘텐츠 자동
공개는 파일럿 근거와 별도 정책이 필요한 후속 범위다. 화행·방향별 위험이나 표본 검출률을
이 구현만으로 확정하지 않는다.

## 구현

- 최신 `origin/main@beb936d4a3414c4210fcce56471018e4569a56d5`에서
  `codex/instructor-review-experience-2026-09-05` 작업공간을 분리했다. 기존 루트의 변경은 보존했다.
- 검수 화면에서 대상을 선택해 규칙 검사 → OpenAI → Claude → OpenAI 지적별 판정을 한 번에
  시작한다. 완료 단계는 재사용하고 유료 단계는 단계별 최대 한 번만 실행한다. 실패·잠금·버전
  변경은 중단 사유로 표시하며, 교수자 승인을 자동 실행하지 않는다.
- 실행 대기열은 같은 탭의 화면 이동 동안 유지된다. 새로고침·탭 종료는 다음 호출을 중단하며,
  서버에 저장된 완료 단계는 다시 시작할 때 재사용한다. 상시 백엔드 작업 서비스는 추가하지 않았다.
- 현재 서버 검수 스냅샷을 기존 학생용 장면·MJT5·핵심 정리·DCT 컴포넌트로 보여 준다.
  직접 풀기/참고 판정 보기, 구성요소별 확인·수정 요청·보류·메모와 관련 AI 지적을 연결했다.
- 수정 요청은 자동 재생성 명령이 아니다. 기존 편집 경로에서 내용을 수정하면 새 버전으로 감수한다.
- `20260905150000_instructor_review_experience.sql`은 현재 버전에 확인 기록·교수자·시각을
  저장한다. 미확인·수정 요청·보류가 있는 감수 기록은 DB에서 승인되지 않고, 기존 기록을 지워
  우회할 수 없다. 과거 승인 자료에는 새 감수 기록을 소급 부여하지 않는다.
- 감수는 학습 수행 저장·이벤트·실시간 DCT 피드백 요청을 실행하지 않는다. 통역 음성 서비스는
  해당 재생/녹음 버튼을 눌렀을 때만 사용한다. 활성 감수 시간은 탭 표시·포커스 기준 근사값이다.

## 반영 경계와 다음 단계

로컬 구현·검증 단계다. DB migration·Edge 배포·PR 병합·운영 공개는 아직 하지 않았다.
`docs/operations/AI_CROSS_REVIEW_PROTOCOL.md`의 DB migration 검토 기준에 따라 승인 경계만
독립 검토한다. 운영 적용 순서는 검토 결과 반영 → DB migration → content-review Edge →
필수 CI를 통과한 main 웹앱 배포다. 실제 콘텐츠의 최종 승인은 교수자가 수행한다.

기능 커밋은 `3b7f0dcc56d7852baf51a4ba936f688cd51d39b9`이다. 해당 clean commit을 대상으로
Claude Code를 Read/Grep/Glob만 허용한 읽기 전용 모드로 호출했으나, OAuth access token invalid
인증 오류(401)로 종료되어 독립 검토 결과는 확보하지 못했다. 코드 검토 실패와 구분하며,
재인증 전 동일 요청을 반복하지 않았다. 운영 반영은 진행하지 않았다.

재개할 독립 검토의 질문은 다음 세 가지로 한정한다.

1. 새 SQL과 기존 승인 RPC에서 관리자 외 기록 변경 또는 저장된 미완료/수정/보류의 승인 우회가 가능한가?
2. `expectedVersion`, 현재 source/content hash, 큐 종료 후 재조회가 변경 전 기록을 새 콘텐츠에 적용하는가?
3. `CanonicalReviewStage`와 체험 저장 경로가 교수자 최종 행동 없이 승인 또는 학습 수행 기록을 만드는가?

`InstructorReviewExperience.tsx`, `reviewPreparation.ts`/`reviewPreparationQueue.ts`,
`contentReviewApi.ts`, `content-review/index.ts`와 직접 연결된 기존 승인 함수만 읽는다.
전체 테스트·설계 검토를 반복하지 않고 배포 차단 결함과 운영 미확인 사항을 구분한다.
