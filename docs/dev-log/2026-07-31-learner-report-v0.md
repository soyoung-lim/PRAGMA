# 2026-07-31 — 학습 기록을 근거 기반 개인 리포트 v0로 전환

담당: Codex(개발) / Claude Code(1차 감수)

## 시작 문제

- `/learner/records`가 최초안·최종안 카드의 시간순 목록에 머물러, 1~15주 동안 무엇이
  쌓이고 다음 수업과 어떻게 연결되는지 학습자가 파악하기 어려웠다.
- 반대로 4·8·15주 성장 단계, 숙달도 게이지, 상황 민감도나 “실력이 늘었다”는 문구를
  바로 붙이면 현재 로그와 계산 계약으로 방어할 수 없었다.
- `revision_target_selected`는 학습자 선택이 아니라 시스템이 지정한 수정 지점이며,
  `first_response != revised_response`만 실제 수정 행동으로 셀 수 있다.

## 구현

- 학습 기록 화면을 다음 구조로 재편했다.
  - 최근 4회·8회·전체 수행 범위 전환(주차가 아니라 **수행 회차**라고 명시)
  - 개인 이름과 관찰 문장
  - `지금 확인되는 강점`·`자주 꺼낸 표현`·`다음 수업에서 해볼 일` 3개 카드
  - 모든 요약 문장을 뒷받침하는 근거표
  - 원문·최초안·최종안의 대표 수정 과정
  - 주장 경계와 전체 수행 원장을 접힌 상세 영역으로 보존
- 순수 집계 모듈 `learnerReport.ts`를 신설했다.
  - 수행 수, 실제 수정 수, 최다 화행, 시스템 지정 수정 초점, 최다 target feature를 집계
  - 최초안에서 해당 feature·산출 언어의 카탈로그 예시를 찾고, 서로 다른 두 수행 이상에
    나타난 경우만 “반복”으로 표시
  - 다음 행동은 가장 최근 수행의 target feature에 연결된 고정 문구를 사용하며 새 AI 호출은 하지 않음
- 로그 조회에 `target_lang`, 프로필 조회에 `full_name`을 추가했다. migration은 없다.
- localhost 임시 학습자는 DB 로그를 저장하지 못하므로, DEV + dev stub + 실제 기록 0건일
  때만 `김민준` 15회 예시를 명시적 배지와 함께 표시한다. production에서는 사용하지 않는다.
- 리포트 화면에만 공통 shell의 넓은 읽기 폭(`max-w-5xl`)을 사용하고 다른 학습자 화면의
  폭은 바꾸지 않았다.

## 주장 경계

- 표시하지 않음: 주차별 성장, 향상도, 숙달도, 점수, 등급, streak·XP·배지·SRS,
  P·D·R 민감도, MPJ 판단–DCT 산출 불일치.

## Claude Code 1차 감수 반영

- `clear`는 세 층을 모두 통과해 고칠 것이 없다는 판정이므로 수정 초점에서 제외했다.
- 최다 수정 초점은 **실제로 수정했고 시스템이 초점을 지정한 수행**만 분모로 삼도록
  머리 문장과 근거표를 일치시켰다.
- 실제 수정 수행이 없으면 대표 수정 과정을 감추고, 최초안과 같은 문장을 최종안으로
  반복 표시하지 않는다.
- 환경 없는 실행의 **169 pass, 3 skip + 4 suite 시작 실패**와 루트 `.env`를 주입한
  실행을 구분했다. 현재 동일 환경의 최종 기준은 **184 pass, 6 skip**이다.
- localhost에서 수정 0회 예시를 임시로 주입해 수정 초점 행과 대표 수정 카드가 모두
  사라지고 `1회 중 0회 실제 수정`만 표시되는 것을 확인한 뒤 15회 예시로 원복했다.

## 학습자 중심 presentation 2차 개선

- 동급 3카드를 깨고 **실제 수정 행동 2/3 + 다음 도전 1/3**의 비대칭 히어로로 재편했다.
  큰 수치는 `실제 수정 n회 / 수행 n회`로 명시해 점수·숙달도처럼 읽히지 않게 했다.
- 반복 표현·수정 초점·화행은 성공이나 약점이 아닌 **눈에 띈 선택**으로 베이지색 중립
  카드에 배치했다. 표현 빈도를 편중이나 능력으로 해석하지 않는다.
- 다음 도전은 누적 최다 feature가 아니라 가장 최근 수행의 feature를 따르며, 최근
  feature와 반복 표현이 일치할 때만 해당 표현을 바꿔 써 보는 대조 실험을 제안한다.
- 수정 초점은 1회·2회·3회 이상으로 문구 강도를 나눴다. 3회 미만에는 `가장 자주`나
  `습관`을 사용하지 않는다.
- 대표 수정은 중국어를 16px로 키우고 추가분에 노란 배경·밑줄을 적용했다. 변경 설명은
  저장된 수정 초점까지만 사용하며 diff에서 의미를 새로 추론하지 않는다.
- 전체 원장은 항목별 요약→상세 아코디언으로 압축하고, 근거표는 쉬운 헤더로 바꿔 화면
  최하단 `분석 근거 자세히 보기` 안에 보존했다.
- localhost 627px 폭에서 단일 열, 수평 overflow 없음(`innerWidth 627`,
  `scrollWidth 612`), 최근 4회 전환, 15건 압축 원장과 개별 기록 펼치기, 분석 근거
  펼치기, 최종 reload 이후 콘솔 오류 0을 확인했다.

## Claude Code 2차 검수·수정 (역할 전환: Claude=개발, Codex=감수)

- **조사 하드코딩 수정**: `‘${라벨}’을`·`’과`가 고정돼 있어 모음으로 끝나는 초점 라벨
  (책임 인정과 수리 / 평가 강도와 민감도 / 문제 명료화와 책임 범위)에서 "수리을",
  "민감도과"로 깨졌다. `learnerReport.ts`에 받침 판정 `josa()`를 추가하고 헤드라인·
  다음 행동 폴백·기록 카드·다음 도전 설명·대표 수정 문구 6곳에 적용. 회귀 테스트 1건 추가.
- **수정 0회 히어로 카드**: 실계정 저데이터 상태(수행 1·수정 0)를 localhost 실화면으로
  확인한 결과, "잘 이어온 행동" 카드에 거대한 `0`이 떠 문구("수행을 끝까지 남겼어요")와
  모순됐다. 수정 0회일 때는 확인된 행동인 수행 완료 횟수를 큰 수치로 대신 표시한다
  (`1회 수행 완료`). 주장 경계 불변 — 새 판정 없음.
- **근거표 문구 일치**: 수정 0회인데 해석 열이 "피드백을 표현 수정으로 연결한 행동"으로
  단정하던 것을 "아직 수정으로 이어진 기록은 없음"으로 분기.
- **단일 칩 정리**: 수행 4회 이하에서는 범위 선택지가 "전체 N회" 하나뿐이라 항상 눌린
  칩 하나만 남았다 — 선택지가 1개면 범위 내비게이션을 렌더하지 않는다(안내 문구는 유지).
- 검증: typecheck 통과 · 전체 Vitest **185 pass, 6 skip**(새 josa 테스트 포함) ·
  localhost 실화면 2종(실계정 1회 저데이터 = 8080, dev 스텁 15회 예시 = 8099)에서
  히어로 전환·조사 표기·범위 토글 재계산·근거표 분기·콘솔 오류 0 확인.
- Codex 1차 보고(181 pass)와 재실행(169 pass) 수치 차이의 원인 = worktree에 `.env`
  부재로 Supabase 의존 4 suite가 시작 전 실패. `.env` 복사 후 동일 환경 기준으로 통일.

## One-page 누적 프로파일 V1 로컬 전환

- 사용자 평가에서 v0가 근거를 모두 보존하느라 긴 관리자 보고서처럼 읽힌다는 문제가
  확인됐다. Pattern Dossier와 다중 차트 대시보드 대안도 검토했으나, 학습자가 별도
  탐색 없이 한 화면에서 읽을 수 있는 단일 프로파일로 범위를 다시 줄였다.
- `/learner/records`를 다음 여섯 요소만 남긴 one-page 구조로 교체했다.
  1. 15회 누적 기록 스트립
  2. 가장 근거가 많은 동일 조건 집단의 핵심 패턴 한 문장
  3. 반복·최근 시도·실제 수정 행동을 보여 주는 짧은 근거 수치 3개
  4. 해당 집단의 AI 피드백 판정 누적 막대 1개
  5. 다음 미션에서 시험할 표현 행동 1개
  6. 피드백 뒤 실제로 고쳐 쓴 DCT 문장을 모은 `나의 수정 노트`
- 비교 단위는 `speech_act + feature_id + task_type + target_lang + feature version +
  feedback rubric version`이 모두 같은 수행의 **최초 산출**로 제한했다. 서로 다른 화행,
  통번역 방식, 학습 초점이나 판정 버전을 합쳐 개인 성향처럼 보이지 않는다.
- 기능별 대역은 능력 점수로 바꾸지 않고 `수행별 AI 피드백 판정`으로 표시한다. 유효한
  관찰 3건 이상이며 동일 비적정 방향이 2회 이상일 때만 핵심 패턴에 올리고, 그보다
  적으면 저데이터 관찰 문장만 보여 준다.
- `선택권을 덜 남김`, `조건절 사용`, `표현을 다시 씀` 같은 분석자 용어는 각각
  `조금 단정적으로 부탁했어요`, `“가능하다면…”을 써봤어요`, `피드백을 보고 문장을
  고쳤어요`처럼 학습자가 수행 장면을 떠올릴 수 있는 말로 바꿨다. 세 수치는 큰 카드가
  아니라 한 줄 지표 스트립으로 압축했다.
- DEV 예시는 기존 삼중 게이트를 유지하며 15회 중 비교 가능한 요청·번역·동일 초점 8건을
  사용한다. production의 실제 기록에는 예시가 섞이지 않는다.
- 디펜스를 통과한 선행 시스템 화면에서 차트 종류나 일반 LMS 지표가 아니라 강한 그리드,
  기록과 분석의 시각적 분리, 일관된 카드 문법을 선택적으로 가져왔다. 프로파일·차트·다음
  행동·수정 노트에 같은 border·radius·shadow·간격 체계를 적용했다.
- `김민준`은 화면 검토용 예시였으므로 개인 이름 표시를 제거하고 `나의 누적 학습 기록`과
  `예시 데이터`로 중립화했다. 이 변경으로 리포트만을 위해 추가했던 프로필 `full_name`
  조회와 타입 변경도 제거했다.
- 대표 diff 한 건은 DCT 누적 자산을 충분히 활용하지 못해 `나의 수정 노트`로 대체했다.
  `first_response != revised_response`인 수행만 모으고, 각 행에 화행·최초 표현·최종 표현·
  저장된 수정 범위 또는 feature 기반의 쉬운 이유를 표시한다. 패널 높이는 고정해 one-page
  밀도를 유지하며 동일 패널 안에서 전체 수정 문장을 스크롤해 볼 수 있다.

## Pattern Dossier 정적 대안 목업

- 사용자가 2차 presentation을 “퍼져 있고 읽기 싫은 관리자 보고서”로 평가해, React
  화면을 더 수정하지 않고 독립 정적 목업으로 대안을 만들었다.
- 한 화면에는 핵심 패턴 하나, 반례, 다음 확인 과제, 수행별 근거 지도와 대표 diff만 둔다.

  패턴 문장은 예시 데이터다. 현행 리포트 계산이나 DB에 연결하지 않았다.
