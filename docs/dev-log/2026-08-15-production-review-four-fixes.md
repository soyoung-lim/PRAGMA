# 운영 전수 검토 잔여 4건 보정

## 문제

- 관리자 라우트는 살아 있었지만 공통 사이드바와 대시보드에서 8개 운영 화면의 진입 경로가 사라져 있었다. 모바일에서는 사이드바가 숨겨져 관리자 화면 사이를 이동할 방법도 없었다.
- 기존 3화행 Seed30을 최종 9화행 기준답안으로 확대 해석하면, 화행당 2개 외부 표본 뒤에 남는 예비 사례가 부족했다.
- 학습자 홈에서 연결되는 공개 설명 화면이 현행 `MPJ4+DCT1` 계약과 달리 `MPJ 5`를 하드코딩했다.
- 외부 전문가 2인이 토론 뒤에도 합의하지 못했을 때의 최종 상태와 공개 차단 규칙이 없었다.

## 변경

- 관리자 내비게이션을 `src/lib/admin/adminNavigation.ts`의 단일 설정으로 옮기고 통합 검수·승인, 시나리오 아카이브, 수업 자료 생성, 학습자 관리, 수행·의사결정 기록, 학습 분석, 학습 콘텐츠 개선, 수행기록 내려받기를 사이드바·모바일 선택기·대시보드 바로가기에 복구했다. 구 `/admin/review`는 현행 통합 검수·승인 화면으로 연결한다.
- 기존 3화행 30건은 초기 `Seed30`으로 명시하고, 최종 9화행 Gold를 `9×5=45`로 고정했다. 최초 외부 표본은 `9×2=18`, 예비는 화행당 3건·총 27건이다. 45건·화행당 5건이 아니면 표본계획·회귀·최종 생성 잠금을 열지 않는다.
- `Architecture`와 `Roadmap`의 공개 MPJ 설명을 `MPJ_ITEM_COUNT`에서 렌더링하게 하고, 공개 설명 화면에서 MPJ5 표현이 다시 들어오지 않도록 계약 테스트 범위를 넓혔다.
- 실제로 서로 다른 두 전문가 판정이 같은 라운드에 존재하고 토론 후에도 합의하지 못하면 append-only `terminal_nonconsensus`로 기록한다. 연구자 단독 재정이나 자동 다수결은 금지하고, 해당 사례를 제외하며 같은 화행의 예비 3건을 모두 개방하고 현재 팩 공개를 보류한다. 임시 미결은 별도 진행 상태로 유지한다.

## 경계와 확인 필요

- 최종 Gold45의 45개 사례를 새로 만들어 승인한 것이 아니다. 현행 Seed30은 초기 3화행 자산으로 보존되며, 최종 gate는 별도 9화행×5 사례가 준비되기 전까지 닫혀 있다.
- PR #18과 lint 보정 PR #19를 main에 병합했다. migration `20260815190000`, `20260815193000`, `20260815194000`을 운영 DB에 적용했고 재 dry-run은 최신이었다. 새 배열 타입 경고는 제거됐으며 기존 확장 준비도 함수의 미사용 변수 경고만 남았다.
- `generate-scenario` Edge v64는 ACTIVE이고 Railway deployment `ca2657be-a136-4788-bb4a-cb139ca5bfd3`는 SUCCESS다. 운영 홈·`/architecture`·`/admin`·`/admin/export`는 HTTP 200을 반환했다.
- `/admin/archive`는 폐기된 구 schema 화면 대신 유지되는 `/admin/library`로 연결한다. `/admin/package`와 `/admin/analytics`는 진입 경로를 복구했지만 화면 자체의 준비 중 상태는 유지한다.
