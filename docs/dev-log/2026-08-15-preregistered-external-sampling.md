# 사전 등록 외부 표본과 30·18·504 증거 경계 분리

## 수행한 변경

- 정식 504개 생성 전에 현재 연구자 승인 Gold 모집단을 고정하고, 서버 계산 시드로 9화행×2건과 화행별 예비 사례를 추출하는 append-only 표본계획을 추가했다.
- 최초 표본에서 한 전문가라도 수정·제외를 선택하면 해당 화행의 예비 사례를 모두 추가 확인하고, 예비 사례에서도 문제가 나오면 해당 화행과 원자적 504개 공개를 보류하도록 DB 배정·readiness gate를 연결했다.
- 90%·95% 내부 운영 게이트의 출처를 연구자 기준답안 30건 이상으로 분리했다. 외부 18건은 내용타당성 독립 확인으로만 표시하고 대표 일치율·카파를 노출하지 않는다.
- 504개 연구자 확인을 자동 통과 결과 확인과 경고 문항 집중 검토로 정의하고, 문항별 자동 경고·확인 방식·시작시각·소요시간을 저장하도록 했다.
- 관리자 화면과 운영 runbook에서 세 근거의 표본·결론을 분리했다.

## 검증

- `npm.cmd run typecheck`
- `npm.cmd test -- --run src/lib/pragma/moatMigrationContracts.test.ts src/lib/pragma/reviewWorkload.test.ts`
- `npm.cmd run build`
- `npx.cmd supabase db push --linked --dry-run`
- 결과: typecheck 통과, 전체 173개 테스트 통과(4개 환경 의존 테스트 제외), 1,918-module production build 통과.
- 세 migration을 원격 DB에 적용했고 최종 dry-run은 최신 상태였다. 최초 lint가 발견한 JSONB 정렬식 타입 오류는 적용 이력을 보존한 두 follow-up migration으로 보정했으며, 재검사에서 새 함수 오류는 0건이었다. 남은 경고는 이번 변경 전부터 있던 `get_pragma_moat_expansion_readiness`의 배열 초기화·미사용 변수뿐이다.
- localhost에서 전체 현황, 외부 표본 확인, 504 자동 결과 확인, 최종 사용 승인 화면의 DOM 문구를 확인했다. 30·18·504의 대상·담당·결론이 각각 분리돼 표시되며 외부 18건에 일치율·카파가 노출되지 않았다.

## 실제로 하지 않은 일

- 실제 표본계획, 전문가 배정·판정, 연구자 504 판정 또는 최종 공개 행은 생성하지 않았다.
- 45~60분 전문가 소요시간과 경고·무경고 문항별 연구자 소요시간은 아직 실측값이 아니다.
