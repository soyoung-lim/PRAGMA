# 2026-08-03 오류 패턴 시드의 산출 방향 필터

## 관찰

- `errorPatternsForAct(act)`가 **화행만 거르고 산출 방향을 거르지 않았다**.
- 카탈로그 6개 중 **4개가 중국어 산출 전용**이다: `direct_negation_fronting`(不行),
  `weak_internal_mitigation`(把…发给我·能不能), `hanja_interference`(발표→发表),
  `ba_imperative_overuse`(把). `excessive_gratitude`도 승인 예시가 중국어다.
- 따라서 **zh_ko(한국어 산출) 미션에 중국어 오답 시드가 주입**됐다.
  `speech_act='request'` 기준 반환 4건 중 3건이 방향 오류였다(learner_verbosity만 유효).
- 2026-08-02 심야 조립 실패 표본 4건이 전부 중→한이었다. 인과는 확인하지 않았고,
  실패는 R27·R5로 별도 설명된다. **가능한 기여 요인으로만 기록한다.**

## 변경

- `ErrorPattern`에 `applicableDirections?: LanguageDirection[]` 추가. 비우면 방향 무관.
- 중국어 자원·예문에 매인 5개를 `["ko_zh"]`로 한정. `learner_verbosity`만 양방향
  (설명·예시가 목표어에 매이지 않는다).
- `errorPatternsForAct(act, direction)`으로 시그니처 변경. 호출부 3곳 갱신
  (`promoteMission.ts`는 기존 `direction`을 그대로 전달, golden 셀은 방향 축이 없어
  `"ko_zh"` 고정).
- 회귀 테스트 5건 신설(`errorPatterns.test.ts`).

시드가 비면 프롬프트의 해당 절이 통째로 빠질 뿐이다(원래 "의무 아님" 시드).
**틀린 언어의 시드를 주는 것보다 비는 편이 낫다.**

## 드러난 공백

**zh_ko 전용 오류 패턴이 하나도 없다.** 이 사실을 테스트로 고정해 두었다.

중→한은 학습자가 **모어를 산출**하는 과제라 "표현을 몰라서" 틀리지 않는다. 쟁점은
원발화의 태도를 어디까지 옮기는가, 즉 매개(mediation) 판단이다. 따라서 ko_zh 패턴을
번역해 옮길 수 없고 별도로 설계·승인해야 한다.

  기존 생성분은 소급 영향이 없다(시드는 생성 시점에만 쓰인다).

- 사용자 결정(2026-08-03): **중→한도 9화행을 모두 갖춘다.** 현행
  `ZH_KO_VALIDATION_ACTS`는 요청·거절·감사 3화행으로, 생성계약 0-l·89가 정한
  파일럿 범위다(18셀, 확장은 눈검사 후 별도 결정). 9화행 확대는 그 범위를 넓히는
