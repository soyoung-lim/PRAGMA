# 정적 설계 화면의 현행 계약 정렬

## 문제

- `/admin/question-designer`가 현행 미션 생성에 쓰지 않는 수준별 문항 비율, 후보 수 3·5·7, 직접성 단일축을 현재 정책처럼 설명했다.
- `/architecture`에 폐기된 사전·중간·사후 평가와 이중 평정, 현행과 다른 학습 흐름이 남아 있었다.
- 정적 설명 화면을 손으로 갱신하면 생성 코드가 바뀔 때 다시 어긋날 위험이 있었다.

## 변경

- 수준 정책을 `src/lib/pragma/levelPolicy.ts`로 분리하고 실제 미션 생성과 관리자 설명 화면이 함께 사용하도록 연결했다.
- 문항 정책 화면을 현행 미션 구조(MPJ 5개 + 산출 1개), 수준별 언어 복잡도·표현 자원·원문 길이, 화행별 목표 요소의 세 대역 판정으로 다시 작성했다.
- 기준답안의 A·B·C 세 후보는 교정 사례이며 실제 학습 미션의 수준별 후보 수가 아님을 명시했다.
- 전체 시스템 구조 화면을 현재 4단계 품질 검증·공개, 실제 학습자 미션 흐름, 동의·가명화·수행기록 추출 경계에 맞췄다.
- 공개 책임은 `시스템의 조건 확인 + 교수자의 최종 학습자 사용 승인`으로 통일했다.

## 주장 경계

- `80%·30%·10%` 수준별 비율은 해당 정적 화면 외의 정본·실행 코드에서 확인되지 않아 채택하지 않았다.
- 이 변경은 화면 설명을 현행 계약과 맞춘 것이며 새로운 학습효과나 콘텐츠 품질을 검증한 결과가 아니다.
