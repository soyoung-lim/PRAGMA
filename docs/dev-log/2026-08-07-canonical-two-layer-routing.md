# 2026-08-07 · 정본 2층 구조와 경로 회귀검사

## 시작 문제

- 날짜별 새 파일 발행은 사람이 읽고 논문에서 인용할 설계 이정표를 남기려는 의도적인
  기록 방식이었다.
- 그러나 현행 규범과 역사 기록이 같은 `_정본_날짜` 이름을 사용했고, 7월 29일 파일도 이후
  계속 수정돼 날짜가 발행일·버전·대조일 중 무엇인지 경로만으로 알 수 없었다.
- AI가 7월 23일 계약의 MPJ5 문장을 현행으로 읽은 사건을 계기로 코드·정본·라우팅을 재감사했다.

## 확인한 사실

- `src/lib/pragma/missionSchema.ts`의 현행 `mission_v5`는 MPJ 항목 4개와 DCT 1개다.
- 기존 `mission_v1/v2`만 legacy MPJ5로 읽는다. `mission_v5`의 5는 문항 수가 아니라 스키마
  버전이다.
- 현행 3종의 본문은 MPJ4와 최근 통역 역할 계약을 반영했지만, 상위 폴더에는 날짜 정본이
  복수 남고 7월 23일 전문에는 강한 MPJ5 문장이 남아 있었다.
- 7월 29일 파일은 8월 6일까지 갱신됐으므로 정확한 7월 29일 동결 스냅숏이라고 볼 수 없다.

## 변경

- `docs/CANONICAL.md`에 날짜 없는 현행 경로 3개를 선언했다.
- 현행 계약·학습자·관리자 정본을 각각 날짜 없는 `_정본.md`로 옮겼다.
- 전환 전 날짜 판본 7개는 삭제하지 않고 `history/legacy/`에 보존했다. 7월 23일 생성계약은
  처음의 축약 시도를 철회하고 Git blob 160,879 bytes 원문을 복원했다.
- `history/`에는 이정표 시점에만 새 스냅숏을 발행하고, 발행 커밋 뒤에는 수정하지 않는 규칙을
  추가했다. `legacy/` 날짜는 정확한 동결 시점을 보장하지 않으며 특정 시점은 Git으로 확인한다.
- `AGENTS.md`와 `CLAUDE.md`가 같은 manifest와 세 경로를 읽도록 맞췄다.
- 과거 의사결정·증거가 날짜 파일을 참조하는 경우 history 경로로, 현재 계약을 참조하는 경우
  날짜 없는 경로로 수정했다.
- 새 콜드 오픈 커밋 `e2de51b`까지 학습자 정본을 재대조해 3장 진입 흐름을 반영했다.
- 정본 경로·날짜 정본 잔존·에이전트 경로 일치·history 비규범성·MPJ4 기준을 검사하는
  `canonicalRouting.test.ts`를 추가했다.
