# 수업자료 교실 출력·강의계획서 연결

- 날짜: 2026-08-26
- 목표: 새 콘텐츠 생성기를 만들지 않고, 승인 미션과 15주 편성 데이터를 실제 수업에서 바로 쓰는
  출력물로 연결한다.

## 결정

- 교수자 수업자료의 정본은 계속 승인된 `mission_content`다.
- 같은 6단계 자료를 교수자 문서, 정답 없는 학생 활동지, 단계별 교실 큰 화면으로 투영한다.
- 학생 활동지에는 해설·정답·참고안을 넣지 않고 직접 작성 공간만 둔다.
- 교실 큰 화면에서는 한 단계만 표시하고 2–5단계 해설은 교수자가 공개할 때만 보인다.
- 15주 강의계획서는 `/admin/composer`의 현재 outline·weeks·미션 배정을 사용한다.
- PRAGMA가 알 수 없는 평가·출결·교재 정보는 생성하지 않고 교수자 기입란으로 남긴다.
- 새 DB, 런타임 AI 호출, 별도 교안 저장소, PPT 생성기는 추가하지 않았다.

## 구현

- `/admin/package`에 `교실 큰 화면`, `학생 활동지 인쇄`, `교수자용 인쇄·PDF`를 추가했다.
- 큰 화면은 1–6 단계 이동, 해설 공개/숨기기, 키보드 이동을 지원한다.
- DCT 단계는 최초 산출→최소 피드백→수정→참고안 비교 순서를 드러내도록 정리했다.
- `/admin/composer`에 `강의계획서` 진입과 A4 가로 인쇄·PDF 출력을 추가했다.
- 강의계획서에는 실제 교과목 메타, 학기 목표, 화행, 주차별 can-do와 미션 세트 A·B를 표시한다.

- 관리자 공통 셸에서 생성→검수→15주 편성·수업자료→학습 수행→기록·내보내기의 현재 단계와
  다음 행동을 표시한다. 별도 대시보드나 새 데이터 구조는 추가하지 않았다.
- 검토 완료 미션은 미션 조립 화면에서 15주 편성으로, 편성된 각 미션은 해당 6단계 수업자료로
  직접 이동할 수 있다.
- 강의계획서 주차표에 실제 편성 미션을 바탕으로 수업활동과 과제·산출물을 추가했다.

  교수자가 평가 비중·출결·과제·교재·담당 정보를 직접 입력하도록 했다. 평가 비중을 입력하면
  합계 100%를 검사한다.

  입력은 단일 관리자 사용을 전제로 교과목별 브라우저 저장을 사용한다.
- 표적 테스트 3파일 7개와 typecheck가 통과했다. 테스트 첫 실행은 샌드박스가 공유 Node 의존성

## 후속 완성 · 30·50·90분 수업 시간 프리셋

- `/admin/package`의 기존 교수자 수업자료에 30·50·90분 운영 프리셋을 추가했다. 새 생성기·메뉴·
  DB·AI 호출은 만들지 않았다.
- 30분은 MPJ5+DCT1 한 세트 20분과 토론·5 POINT LESSON 10분, 50분은 한 세트 수행을 수정·
  참고안 비교와 전이 활동까지 확장하는 구성이다.
- 90분은 한 세트를 늘여 쓰지 않고 같은 화행의 독립적인 완결 미션 1·2를 60분간 수행한 뒤,
  두 수행의 선택·수정 근거를 나란히 정리하고 새 상황에 적용하는 활동을 30분간 진행한다.
- 각 프리셋은 활동명·소요 시간·진행 방법·학습 산출물을 표시하고 총 시간이 선택값과 정확히
  일치하도록 결정론적 상수로 관리한다. 같은 운영표를 교수자 화면과 교수자 인쇄물에 투영하며
  학생 활동지에는 노출하지 않는다.
- `npm.cmd run typecheck`와 표적 테스트 2파일 7개가 통과했다. 표적 테스트의 첫 실행은 샌드박스가
  공유 Node 경로를 차단해 시작하지 못했으며, 같은 테스트를 허용된 범위에서 재실행해 통과했다.
- 관련 결정: `DEC-20260826-07`.

## 90분 실제 미션 1·2 연결 판정과 최소 구현

- 판정: `지금 반드시 해결`. 배포된 첫 프리셋은 90분 운영표를 표시했지만 `/admin/package`가
  미션 한 건만 조회·렌더해 두 번째 활동지·교실 화면이 없었다. 90분을 실제 운영 옵션으로 제공하려면
  기존 편성의 두 미션을 같은 수업자료 흐름에 연결해야 한다.
- 새 A/B 실험쌍·변화축·coverage·DB·AI 호출은 만들지 않았다. `/admin/composer`의 같은 주차에 이미
  저장된 첫 두 미션 ID를 `90분 묶음 수업자료` 링크로 전달하고, 수업자료 화면은 같은 화행·수준·
  언어방향·수행모드의 서로 다른 승인 미션만 두 번째 미션으로 허용한다.
- 교수자 자료와 학생 활동지는 미션 1·2를 순서대로 출력하고, 교실 화면은 미션 1의 6단계 뒤 미션 2의
  6단계로 이동한다. 마지막에는 두 수행의 판단·수정 근거를 나란히 적는 한 장 활동만 추가했다.
- `A·B 최소대조` 표현은 정본의 독립 미션 원칙과 충돌하므로 `미션 1·2 판단 근거 비교`로 바꿨다.
  특정 맥락 변수의 효과나 전이 효과를 주장하지 않는다.
- 첫 운영 점검에서 편성 링크가 `mission2`를 정상 전달했지만 수업자료의 빈 초기 목록이 이를 유효하지
  않다고 판정해 쿼리에서 먼저 제거하는 로딩 순서 문제를 발견했다. 미션 목록 로딩 완료 뒤에만 두 번째
  미션 유효성을 판정하도록 고치고 이 순서를 회귀 테스트로 고정했다.
- 표적 테스트 2파일 11개와 `npm.cmd run typecheck`, `git diff --check`가 통과했다. 첫 표적 실행은
  공유 Node 경로의 샌드박스 차단으로 시작하지 못했고 같은 명령을 허용된 범위에서 재실행해 통과했다.

  Railway production deployment `bd93239e-040f-4559-8ff3-a99b2aedcbad`은 `SUCCESS`이며 image
  digest는 `sha256:5430e4d13c6ea0075c8967d3f5c2b9c2fa0c6f3f9e239b1a6e5b006d75247194`다.
- 운영 교과목 `915fec24-cc38-4b00-a2a0-c3628abcd3f7`의 2주차 요청 미션 두 건
