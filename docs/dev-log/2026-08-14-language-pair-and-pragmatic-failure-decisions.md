# 2026-08-14 · 터키어 문제와 사회화용·화용언어 문제 기록

## 목적

향후 박사학위논문 2·3·4장 초안에 반영할 두 설계 쟁점과 최종 원칙을 기억 가능한 형태로 고정한다. 이번 작업은 코드·앱·생성계약을 변경하지 않고 연구 기록만 갱신한다.

## 1. 터키어 문제

### 문제

PRAGMA의 P·D·R, 직접성·완화 눈금과 화행 배치는 다른 언어에도 사용할 수 있다. 따라서 중국어를 터키어·아랍어로 바꿔도 앱이 비슷하게 작동한다면 중국어 연구가 아니라 기술 매뉴얼처럼 보일 수 있다.

### 최종 원칙

- 공통 골격의 이식 가능성은 결함이 아니라 통제를 위한 선택이다.
- 중국어 특수성은 새 수치 축의 개수가 아니라, 한·중 문헌과 검수에 의해 달라지는 적절 대역·목표 표현·매력적 오답·전이 피드백에서 입증한다.
- 논문에서는 이를 `언어 중립적 통제 골격 + 한·중 언어쌍 특화 실현층`으로 설명한다.
- 대표 문항은 문헌→설계 규칙→문항→판정·검수의 연결을 보여 주고, 전체 추적표는 부록에 둔다.

### 기억할 한 문장

> 언어를 바꿔도 엔진은 돌지만, 적절성 판정과 오답·피드백은 전부 다시 명세하고 검수해야 하므로 한·중판의 내용은 그대로 대체할 수 없다.

## 2. 사회화용·화용언어 문제

### 쉬운 구분

- 사회화용적 문제: `이 관계와 상황에서 어느 정도로 말해야 하는가`를 다르게 판단한 경우
- 화용언어적 문제: 의도는 맞지만 `그것을 목표어로 어떻게 표현하는가`에서 어긋난 경우

### PRAGMA에서의 자리

- 적절한 직접성·완화 대역이 어디에 놓이는가 = 사회화용적 판단
- 그 대역을 호칭·어기사·완화 장치·관습 표현으로 어떻게 채우는가 = 화용언어적 실현
- MPJ 판단→이유→통번역 산출→수정 기록은 두 원인을 추정하는 단서다.

### 피드백 원칙

- MPJ 판단부터 어긋남: 사회화용 문제 가능성을 먼저 살핀다.
- 판단은 맞고 산출만 어긋남: 화용언어 문제 가능성을 먼저 살핀다.
- 판단과 산출이 함께 흔들리거나 표현의 힘을 오해함: 혼합·경계 사례로 둔다.
- 자동으로 실패 유형을 확정하거나 화용 능력 점수로 사용하지 않는다.
- 사회화용 피드백은 ‘틀린 문화’가 아니라 관습 차이를 인식하게 하고, 화용언어 피드백은 구체적인 목표어 대안을 제공한다.

### 기억할 한 문장

> 사회화용은 적절 대역의 위치이고, 화용언어는 그 대역을 목표어 표현으로 실현하는 방법이다.

## 3. 현행 구현 실측

### 확인한 구조

- `feedback_v1`의 명시 판정은 `semantic_fidelity`, `grammatical_accuracy`, `pragmatic_appropriateness(feature_code·band_code)` 3층이다. `uncertainty_flags`도 `grammar | pragmatic`만 구분하며 사회화용·화용언어 전용 태그는 없다.
- `targetFeatures.ts`의 각 초점은 상황에 맞는 적절 대역과 중국어·한국어의 실현 자원·배제 혼입 요소를 함께 정의한다. 따라서 현행 `band_code` 하나를 곧바로 사회화용 태그로, `feature_ko`를 화용언어 태그로 등치할 수 없다.
- MPJ 선택·이유·확신도는 `context_judgment`의 `mpj_response_v1`로, 최초·수정 산출과 `feedback_v1`은 같은 수행 행의 `first_response`, `revised_response`, `target_feature_observed`로 저장된다.
- `errorPatterns.ts`에는 내적 완화 부족, 한국어 한자어 간섭 등 화용언어 분석에 참고할 만한 생성 시드가 있으나, 이는 MPJ 오답 후보 생성용 카탈로그이며 학습자 실패 유형 태그로 저장되지 않는다.

### 판정

- 현행 데이터는 MPJ 판단과 산출 결과를 함께 보는 사후 분석의 단서는 제공한다.
- 그러나 MPJ 여러 문항과 산출 과제는 일대일 진단 검사가 아니므로, `MPJ 어긋남 = 사회화용 실패`, `산출 어긋남 = 화용언어 실패`로 자동 확정할 수 없다.
- 현재 단계에서는 스키마에 새 실패 유형을 추가하지 않는다. 먼저 분석 규칙, 경계·혼합 사례, 인간 검토 절차를 별도로 명세한 뒤 구현 여부를 판단한다.
