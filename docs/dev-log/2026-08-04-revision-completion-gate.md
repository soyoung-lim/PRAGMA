# 2026-08-04 · 수정 필요 완료 게이트와 목표 화용 축 우선순위

## 확인된 문제

- 2026-08-03 전체 미션 화면 점검에서 의미는 통과했지만 문법과 상황 적절성이 함께 실패한
  답안의 `revision_scope`가 문법으로 정해졌다.
- 다듬기 화면에 최초 답안이 그대로 들어간 상태에서 `수정 완료`가 활성화돼, Take 2가
  Take 1과 같아도 미션을 완료할 수 있었다.
- 직접 증거는 사용자 캡처 `204310`(문법·상황 적절성 동시 실패), `204330`(문법만 수정
  목표로 제시), `204340`·`204344`(변경 없는 Take 2와 완료)이다.

## 변경

- 실패 상태의 학습자 문구를 `조절 필요/조절할 부분`에서 `수정 필요/수정할 부분`으로 바꿨다.
- 단일 수정 목표의 우선순위를 `의미 → 목표 화용 축 → 문법 → 없음`으로 바꿨다. 세 층의
  독립 판정과 상세 피드백은 유지한다.
- 수정 화면은 최초 답안을 편집용으로 채우되, 빈 답·동일 답·앞뒤 공백만 다른 답에서는
  완료 버튼을 비활성화한다. 내부 공백은 언어별 의미 가능성이 있어 정규화하지 않는다.
- 세 층 모두 통과한 경우의 `이 표현으로 완료`는 그대로 유지한다.
- 저장·누적 기록의 actual revision 판정(`first_response !== revised_response`)은 바꾸지 않고,
  학습자 완료 게이트에만 실질 수정 판정을 추가했다.
- DEV의 명시적 `?preview=v5` 링크가 로그인으로 튕기던 문제는 별도 커밋 `3be51a3`에서
  `preview=v4|v5`만 인증 없이 열도록 보정했다. production 인증 정책은 불변이다.
