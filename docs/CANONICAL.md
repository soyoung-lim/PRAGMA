# PRAGMA 제품 정본 경로

> 상태: 앱 저장소의 정본 탐색 기준. 정본을 열기 전에 이 파일의 정확한 경로를 사용한다.

## 현행 정본

현행 규범 문서는 다음 세 파일뿐이다.

- 생성·평가·저장: `docs/contracts/PRAGMA_생성계약_정본.md`
- 학습자 구조: `docs/product/PRAGMA_학습자구조_정본.md`
- 관리자 구조: `docs/product/PRAGMA_관리자구조_정본.md`

날짜가 없는 `_정본.md` 이름 자체가 현행이라는 신호다. 검색 결과, 수정 시각, 파일 크기,
날짜의 최신값 또는 자동으로 제공된 요약으로 현행본을 추측하지 않는다.

## 최신 학습설계와 운영 구현의 구분

최신 승인 학습설계는 **MPJ5 + DCT1**이다. 다섯 MPJ의 기능은
`첫인상 판단 → 맥락 대비 판단 → 판단하고 고쳐보기 → 이유 찾기 → 여러 초안 비교`이며,
localhost `CanonicalMissionRun`의 다섯 MPJ를 설계 기준으로 삼는다. MPJ5의 한 문항을 제거해 MPJ4로
되돌리는 것은 승인된 설계가 아니다.

현행 소스의 `mission_v5` 생성·검사·러너 계약도 승인된 **MPJ5 + DCT1**에 동기화됐고
운영 DB·Edge·Railway에 반영됐다. 신규 생성 순서는
`scale4 → judge3 → fix_choice → reason → multi_judge`이고, 네이티브 응답은
`mpj_response_v2`로 저장한다. 과거 `mission_v5` MPJ4 행은 legacy 구현으로 읽기 호환하며
자동 변환하지 않는다. 네이티브 MPJ5의 실생성·저장·교수자 검수·학습자 종단은 별도 확인 대상이다.

화행 학습 주차의 수업 단위는 **화행 1개 + 완전한 MPJ5+DCT1 미션 A/B 2세트**다.
주차와 두 미션의 학습목표는 특정 `target_feature` 하나가 아니라 같은 화행의 핵심 화용 판단
묶음이다. `target_feature`는 문항 생성·진단·피드백·근거 추적을 위한 내부 태그로만 사용하며,
주차 또는 미션 전체의 목표로 표시하지 않는다. 수업시간, 주당 수업 횟수와 시간 배분은 앱 계약과
논문 주장 범위에 넣지 않는다.

이 화행 중심 A/B·다차원 coverage는 승인된 **다음 구현 계약**이다. 현재 배포된 개별 미션의
네이티브 MPJ5 구조와 혼동하지 않는다. 현행 관리자 편성·생성기·저장·러너는 아직 A/B 쌍과
합산 coverage를 보장하지 않으므로, 이를 구현하기 전 운영 미션 두 건을 임의로 A/B라고 부르지 않는다.

승인된 경험 구조는 다음과 같다.

- 화행 학습 주차에는 같은 화행의 완전한 미션 두 세트를 A와 B 순서로 편성한다.
- 미션 A와 B는 각각 최초 진입 때 3단 장면 도입을 반드시 거친다.
- A는 `오늘의 장면 → 장면 속 단서 → 당신의 선택`을 사용한다.
- B는 `새로운 장면 → A와 달라진 맥락 → 이번 장면에서의 선택`을 사용하고,
  상대·거리·부담·채널의 관찰 가능한 변화만 보여 주며 정답 방향을 암시하지 않는다.
- A/B는 같은 화행을 유지하되 하나 또는 소수의 맥락 조건을 바꾸고, 두 미션을 합쳐 해당 화행의
  핵심 화용 판단을 복수 맥락에서 다룬다. 이것을 모든 상황의 일반화나 학습효과 입증으로 표현하지 않는다.
- 상단 진행은 `장면 이해 → 표현 판단 → 직접 산출 → 피드백 → 다듬기`의 조용한 5단
  horizontal macro progress를 사용한다. 표현 판단 내부에서는 `표현 판단 n/5`로 표시한다.

실제 구조·문서가 충돌하면 충돌한 파일과 코드·테스트 근거를 함께 보고하고 조용히 어느 한쪽을
최신으로 간주하지 않는다.

## 2층 기록 규칙

1. 현행 정본은 날짜 없는 파일 하나를 제자리에서 수정한다.
2. 변경 이력은 Git이 보존한다.
3. 사람이 읽고 인용할 이정표가 필요할 때만 `history/PRAGMA_자료명_YYYY-MM-DD.md`를 발행한다.
4. 이정표 스냅숏은 발행 커밋 이후 수정하지 않는다. 정정은 새 날짜 스냅숏으로 발행한다.
5. `history/legacy/`는 이 규칙 도입 전에 날짜를 붙여 계속 수정하던 판본이다. 파일명의 날짜가
   정확한 동결 시점을 보장하지 않으므로, 특정 시점의 내용은 Git 커밋으로 확인한다.
6. `history/`와 `history/legacy/`의 파일은 현재 구현 근거로 사용하지 않는다.

이 규칙은 생성계약 3종에만 한정하지 않는다. `fullworkflow01~10`처럼 일련번호·날짜로 누적된
자료도 먼저 `현행 후보 / 역사 자료 / 판정 필요`로 목록화한 뒤 같은 2층 구조를 적용한다.
판정 전에는 파일을 삭제하거나 이름만으로 최신본을 확정하지 않는다.

## 논문 저장소와의 관계

논문 저장소의 `01_정본/00_정본목록.md`는 교차 저장소의 시작 경로를 알려주는 목록이다.
앱 구현 중에는 이 파일과 앱의 세 경로가 일치하는지 대조하되, 불일치하면 한쪽을 추측으로
고치지 않고 보고한다. 앱 저장소의 코드·테스트·계약 변경은 이 저장소 안에서 함께 검증한다.
